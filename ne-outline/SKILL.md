# ne-outline · 细纲与骨架（S1）

## 一、写前必填：内核三联

**缺一项 = 规划不完整，禁止进入 S2。**

```
[目标] 本章主角想要什么？为什么现在想要？        (C-001)
[阻力] 什么阻碍他？哪类阻力？（人/制度/时间/信息/性格/资源/环境/隐性）(C-004)
[后果] 行动后什么状态会改变？（信任/关系/资源/认知/处境）(C-002)
```

**驱动标注**（短篇/长篇通用）：
```
- 制造什么期待（读者在等什么）：
- 第几段/几章后引爆：
- 憋压到什么程度给：
- 读者翻页/追更动力：
```

> 内核表是冻结的，修改走 CCP + 用户批准。完整版见 `./references/narrative-kernel.md` + `./references/upstream/narrative-core.md`。
> **本引擎建立在内核上，不是套路上**——套路可变，支撑故事成立的底层关系不随题材消失。

## 二、产物：四维骨架细纲

文件：`故事/元数据/细纲_第0001章.md`（**4 位章号**）
模板：`./templates/细纲模板.md`

四个维度，缺一不可：

| 维度 | 内容 |
|---|---|
| **冲突链** | 四节点完整（触发→升级→转折→结果） |
| **情绪弧** | 憋压层次 + 释放点 |
| **信息释放** | 本章释放什么信息、对谁释放、保留什么 |
| **声线透传** | 从角色卡引用 + **标注来源**（如 `characters.md#林枫`） |

另需：角色状态最小摘要（执笔态的知识边界）、**任务字数（必须是具体数字）**、伏笔计划。

## 三、细纲门（两层，硬软分开）

| 层 | 判据 | 谁判 |
|---|---|---|
| **结构硬检** | 四维度齐全、冲突链四节点、声线标了来源、任务字数有数字 | `verify.py` 可校验 |
| **删节推理软检** | 写"删掉这一节，下一节会缺什么" | Agent 自检 |

**节级打回 ≤2 轮**：骨架问题回 S1，表达问题回 S2，保留 Best Version。

## 四、章功能分型与任务字数

不同功能的章节，结构与字数预算不同（开场章 / 推进章 / 高潮章 / 过渡章 / 收束章）。
详见 `./references/target-focus.md` 与 `../ne-write/references/workflow-detail.md`。

**任务字数必须写具体数字**，不能写"约 2500"——门禁要读数字做验收（target±15%）。

## 五、门禁

```
python ../ne-tools/runtime/verify.py --root <项目根> --scope outline
```

## 六、下一步

细纲过门后 → 转 `ne-write` 的 S2。**S2 的输入包只有细纲文件**，不要把技法库、状态文件一起递过去——那会毁掉物理隔离。
