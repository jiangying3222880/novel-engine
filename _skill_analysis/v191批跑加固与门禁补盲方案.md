# v1.9.1 批跑加固与门禁补盲方案（P0 正式改造清单）

> 来源：唐末 30 章（MiniMax Code，每章子 Agent）+ 星尘方舟 20 章（豆包，同会话连跑）连续自动批跑实测退化
> 根因结论：窗口隔离防得住"父上下文泄漏"，防不住"输入内容脏"；且技能只定义了"单章怎么写"（single/multi），**没有定义"连写 N 章怎么不崩"（batch）**
> 版本：归入 **v1.9.1 修复批次**（v1.9.0 视为失败需修复，不升大版本；verify.py 注释已用 v1.9.1 标记）
> 状态：**待用户确认后动手**；本文档只做设计，不改代码

---

## 0. 改造范围与原则

- 只改技能（novel-engine），**不动两本小说的项目数据**。
- 机器能确定性判定的 → 进 verify.py（硬门禁，FAIL 退出码 1）；需要语义判断的 → 进 S3 检验报告模板（强制人工/Agent 核对项），**不假装程序能判**。
- 引入 **WARN 级**：现有 verify 只有 PASS/FAIL。趋势、跨章复用这类"可能是有意"的信号用 WARN（打印、不计退出码），避免误伤艺术手法（念名单回环、刻意呼应）。
- 检查项编号续 verify.py 现有 #1–#16，新增 **#17–#32**。

### 1.5 章际连续与收尾雷同（用户新增需求）

> 两个检查点分开：**连续性**（上章结尾→下章开头接得上，语义判断落 S3，见 §4）；**收尾雷同**（多章结尾重复/相似意象，机器可查，落 verify）。
> 现有 #7「落点类型去重」只查细纲标注的开/合/转，是**规划层**；#33 查正文实际结尾，是**成稿层**，两者互补。

| # | 检查名 | 规则（算法） | 判定 | scope | 对应问题 |
|---|--------|-------------|------|-------|---------|
| 33 | **章末雷同（收尾套路化）** | 取每章正文最后 2 个非空段（约末 150 字）为"结尾窗"：① 任意两章结尾窗出现 ≥25 字连续相同片段；≥40 字加重；② 内置收尾套路意象词表 `TAIL_CLICHE`（夕阳/落日/余晖/残阳、背影/身影拉得很长/拉长、长叹/长长吁了口气、夜色/夜幕/月色/星光、握紧拳/目光坚定、渐渐远去/消失在尽头、风起了 等），同一意象在 ≥3 章结尾窗出现 | ① 25–40 字 **WARN** / ≥40 字 **FAIL**；② **WARN**（列章号+意象，防"每章都以夕阳背影收尾"） | all/settle | 用户实例："他看着夕阳，背影拉得很长"在多章结尾出现；收尾意象套路化 |

> #33 说明：词表按题材可扩充（脚本顶部常量，注释标明）；逐字重合抓"复制式雷同"，意象词频抓"换词不换套路"。语义级"异曲同工的收尾意境"机器判不了，落 S3。预防性检查，两书评审未明确列此类章节，阈值先以 WARN 观察、不硬 FAIL（除 ≥40 字逐字）。

## 2. P0-A 连续批跑模式协议（execution-modes.md 新增章节）

execution-modes.md 现有 auto/single/multi 回答"**单章**用什么方式写"；新增 **batch（连续批跑）** 回答"**连写 N 章怎么不崩**"。四条硬规则：

1. **章间硬中断**：每章 S4 必须跑 `verify.py --scope settle`，**FAIL 立即停批**，不得开下一章；不是提醒、不允许"先写后面再补"。
2. **错误不向下游传播**：某章 settle FAIL → 第 N+1 章 S1 启动前先跑 #32 连续性检查，前章未 archived 即拒绝启动（机器闸，不依赖 Agent 自觉）。
3. **上下文水位**：
   - single（同会话连跑）：建议每 **3–5 章主动新开会话**，按 workflow-detail「中断与恢复」靠状态文件+上章检验报告重建；
   - multi（每章子 Agent）：子 Agent 提示词必须由 §3 输入包模板编译，**禁止把上一章正文作文风样本传入**；
   - 两种模式都禁止"为赶进度压缩省略 settle"。
4. **打回留痕**：细纲门/正文门每次打回，在本章流程日志记一行（轮次/骨架还是表达/一句话原因）；S4 检查打回记录存在性，防批跑时赶进度直接放行。

## 4. 机器能力边界（诚实声明，拒绝过度承诺）

以下评审问题**机器做不了确定性判定**，不进 verify，改入 S3 检验报告模板强制核对项（带 evidence）：

| 评审问题 | 为什么机器判不了 | S3 落点 |
|---|---|---|
| **章际连续性**（上章结尾→下章开头必须接得上：时间顺承/地点连续/在场人物一致/上章钩子有回应；反例 29章末"天亮见城墙" vs 30章首"大前天见的"、陈二留守后七人齐发、离洞后仍进出洞口） | 需比对"上章最后一场状态"与"本章第一场状态"的语义 | 检验报告新增**章际衔接核对（连续性四问，必答 + 双侧 evidence）**：① 时间是否顺承（紧接/当日/次日，不得矛盾）；② 地点是否连续（换场有无过渡）；③ 上章末在场人物本章开场是否一致（离开者不得无故在场、留守者不得无故齐发）；④ 上章钩子/悬念本章是否回应。必须引"上章末原文 + 本章首原文"两处证据 |
| 正文级生死/位置冲突（苏铭死两遍、17/18湍流双版本） | 需从正文提取事件并比对 | S3 章际衔接 + #23 表格级兜底 |
| 设定宪法被剧情软化（量子绑定7天→50年；数据vs肉身） | 核心设定一致性是语义推理 | S3 新增**设定宪法核对**：world.md 冻结铁律 vs 本章情节，冲突即打回 |
| 算术硬伤（七份半减五份半=少十份） | 需理解题意列算式 | check_text `--digits` 已能导出数字（观察级）；S3 强制人工核对本章数量变化 |
| 伏笔承诺违约（玻璃答案被晶歌口头替代） | 需判断"回收方式/揭示者是否符合承诺" | S3 伏笔核对：hooks 计划回收方式 vs 实际 |
| 机械降神/零代价（一首歌退敌、30章零冲突） | 美学判断 | 细纲门"代价节点"已有；S3 强化 + 连续 N 章无代价提示（#27 扩展，语义部分仍人工） |
