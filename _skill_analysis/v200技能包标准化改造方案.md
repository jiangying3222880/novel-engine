## 零、先纠正两个前提（实测结论）

**① 目标不是"造一个和 oh-story 一样的包"，是"借它的骨架，装自己的内容"。**

实测 oh-story-claudecode（本机已装 v0.6.21）的组织方式：

| 观察项 | oh-story 实际做法 |
|---|---|
| 包级 manifest | **没有**。12 个 `story-*` 目录平铺在 skills/ 下 |
| 路由 | 单独一个 `story` 技能（SKILL.md 仅 6672 B），只做意图分发 + 降级 + 版本检查 |
| 子技能体量 | SKILL.md 9.4KB ~ 64.5KB（`story-long-write` 64KB）——**它比我们还大** |
| 索引文件 | **没有** README/_README，靠 SKILL.md 自述 |
| 版本 | 单个 `story/VERSION` 文件（内容 `0.6.21`） |
| 维护同步 | 靠 `npx skills add` 整体重装覆盖，**不解决"改了 A 忘了 B"** |

结论：oh-story 的"标准化"= **路由单列 + 子技能自包含 + frontmatter 统一**。
它的短板恰恰是我们要补的：**它没有文档同步机制**。

**② "文档不同步"不是靠人靠 AI 的问题，是工具已有但没接线。**

实测发现 `runtime/doc_sync.py` **早就存在且能跑通**（242 行，v1.9.1.2 专为修 D-18「版本段漏改第 3 次复发」补的全文 token 扫描）：

```
$ python runtime/doc_sync.py scan
[已过期] _skill_analysis  (自动清单与目录不一致)

$ python runtime/doc_sync.py check
[已过期] _skill_analysis  (自动清单与目录不一致)
EXIT: 1          ← 门禁真阻断，功能正常
```

版本号三处一致性实测**是齐的**（SKILL.md frontmatter `version: 1.9.1.3` = README 首行 `v1.9.1.3` = 变更历史顶部 `v1.9.1.3`），doc_sync 没误报。

**真正的问题**：技能文档里几乎查不到 `doc_sync` 的调用要求（只有 library 自动生成区的注释标记），
AI 改完文件不知道要跑它，人也不知道 → 工具形同虚设。

## 一、拆分方案

### 1.1 切分原则

**按"一次会话只干一件事"切，不按文档类型切。**
判断标准：如果用户这次只想写章节，他需要读几个子技能？答案必须是 1~2 个。

### 1.2 目标结构

| 子技能 | 职责 | 主要来源（当前文件） | SKILL.md 预估 |
|---|---|---|---|
| `ne` | **路由**：意图分发、项目状态感知、版本/升级检查 | 现 SKILL.md 路由段 + `routes/index.md`(14.8KB) | ~6KB |
| `ne-setup` | 建项目、真相文件初始化、身份配置 | `project-setup.md`(16.9KB) + templates 项目骨架 | ~10KB |
| `ne-outline` | 细纲/骨架、章功能分型、任务字数 | `细纲模板`(4.8KB) + `narrative-kernel.md`(8.2KB) + `target-focus.md`(6.9KB) | ~9KB |
| `ne-write` | **正文主流程 S1-S4**、执行模式、声音包 | `workflow-detail.md`(20KB) + `writing-guide.md`(17.2KB) + `execution-modes.md`(10.2KB) | ~14KB |
| `ne-review` | 检验、去 AI 味、遮名测试、evidence | `self-review.md`(18.2KB) + `anti-ai.md`(15.3KB) + `anti-ai-词级信号.md`(7.6KB) + `human-signal-zh.md`(11.2KB) + `检验报告模板`(11KB) | ~14KB |
| `ne-memory` | 状态落库、跨会话续写、滚动窗口、检索 | `hooks-and-memory.md`(11.7KB) + `session-start.md`(9.7KB) + `retrieval.md`(9.3KB) | ~10KB |
| `ne-short` | 短篇全流程 | `short-story.md`(16KB) + `short-story-engines.md`(12.1KB) + 短篇模板 | ~12KB |
| `ne-library` | 素材库（技法/类型/身份/知识/平台） | `library/` 158 文件（techniques 124 / genres 16 / knowledge 9 / identities 5） | ~6KB + 全量素材 |
| `ne-tools` | 运行时：门禁、索引、打包、部署 | `runtime/*.py`（verify / doc_sync / package / index / query / check_text …） | ~6KB |

**净效果**：写章节时只需加载 `ne-write` 14KB，而不是现在整个 17KB 主文件 + 35 个 references 的索引。

### 1.3 三个必须定的设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 共享铁律放哪 | **复制到每个子技能 SKILL.md 头部**（几百字） | 自包含优先。跨目录引用会路径耦合，豆包/网页端读不到 |
| `变更历史.md`(45KB) 怎么办 | **移出技能本体**，留开发仓，不进运行镜像 | 它是开发档案不是运行依赖，占镜像体积却从不读 |
| `library/` 158 文件 | 整体归入 `ne-library`，其余技能按**相对路径**引用 | 避免 8 份拷贝；素材是按需取，不常驻上下文 |

## 二、文档同步机制（治根）

三道闸，**全部机器强制，不依赖人或 AI 记得**。

### 闸 1：VERSION 单一真相源（新增）

新增 `VERSION` 文件（学 oh-story），内容如 `1.9.1.3`。
改造 `doc_sync.py` 的 `extract_skill_version()`：优先读 `VERSION`，取不到再回退 SKILL.md frontmatter。
**任何一处版本号必须等于 VERSION，否则 check 失败。**

### 闸 2：git pre-commit hook（治"改了不跑"）

在 `.git/hooks/pre-commit` 装钩子，提交前强制：

```
python runtime/doc_sync.py check   → 非 0 则拒绝提交
```

被拦时的提示要写明怎么修：`python runtime/doc_sync.py update` 刷新自动清单区后重新提交。

> 这直接治死"升级完文档不同步"——**不同步就提交不上去**，与谁改的、记不记得无关。

### 闸 3：`runtime/deploy.py`（治"C 盘镜像"）

现状实测（2026-10-15）：

| | 文件数 | 版本 |
|---|---|---|
| D 盘源仓 | **514** | v1.9.1.3（+v1.9.2 设计稿） |
| C 盘运行镜像 | **1185** | **v1.4.0** |

镜像比源仓多 671 个文件且落后 5 个版本——因为一直是**整目录手工复制**，
把 `_skill_analysis/`、测试基线、`__pycache__` 全复制过去了（正是 `package.py` docstring 里登记的 D-19 问题）。

新增 `deploy.py`：复用 `package.py` 的排除规则，一键把源仓同步到运行镜像，
同步前先删镜像里的陈旧文件（而不是只覆盖），同步后校验 `SKILL.md` 版本号与源仓一致。

### 升级 SOP（写进 `ne` 路由技能，让 AI 每次照做）

```
改完文件 → python runtime/doc_sync.py update
        → git commit        （hook 自动跑 check）
        → python runtime/deploy.py
```

## 三、迁移步骤（拍板后执行）

1. **备份**：`git tag pre-v2-split`，并整目录备份到 `_backup_v1913/`
2. **闸 1+2 先行**（低风险，先享受收益）：加 `VERSION`、改 `doc_sync` 取版本、装 pre-commit hook
3. **闸 3**：写 `deploy.py`，执行一次把 C 盘镜像从 1185/1.4.0 拉齐到 514/v1.9.1.3
4. **拆分**：按 §1.2 表建 9 个子技能目录，`git mv` 迁移文件（保留历史）
5. **改 doc_sync**：从"单技能根目录"改为"遍历所有 `ne-*` 子技能"逐个校验
6. **回归**：跑 `verify.py --scope all` + `doc_sync.py check` + 实际写一章验证路由能走通

## 四、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 路由能力依赖宿主 | 豆包/网页版无子技能自动路由 | `ne` 路由技能内置降级：识别意图后**把子技能核心指令内联展开**，不依赖宿主路由 |
| 跨技能引用路径耦合 | `ne-write` 要读 `ne-library` 的技法 | 统一约定 `<技能根>/../ne-library/...` 相对路径，doc_sync 增加**跨技能断链检查** |
| 拆分后总文件数增加 | 9 份 SKILL.md + 9 份 references | 共享铁律只复制几百字；大素材不复制 |
| 与上游 oh-story 冲突 | 不 conflict——我们不 fork 它 | 只借骨架，不改它的任何文件 |
| 拆分期间不能写作 | 迁移中技能处于半状态 | 先在 `_v2/` 新目录搭好，验收通过后再切换镜像指向 |
