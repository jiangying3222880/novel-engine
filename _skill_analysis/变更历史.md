> 触发：主人一句「声音样本核实一下，是小说角色的声音还是作者的声音样本」。

### 核实结论：是作者的叙述声线，不是角色声线

仓库里其实并存两套声线，但**没有任何一处写明它们是两回事**：

| | 作者声线（§5.2 本区） | 角色声线（另一套） |
|---|---|---|
| 谁的嘴 | 作者的笔：叙述/描写/动作/心理转述 | 每个角色的嘴：说出来的话 |
| 落点 | `配置/身份/作者.md` §5.2 | `设定/角色声线.md`（模板 `voice-profile-template.md`） |
| 谁负责 | 作者·决策态（立项时定） | 编剧·S1（从 characters.md 透传进细纲 §5，标来源） |
| 机器闸 | **原本没有**（v2.1.4 补 #29c） | 有：verify 校验细纲 §5 标了来源 + S3 遮名测试 Q2a |

### 改了什么

1. **作者档案 §5.2 开头加"两层声线"对照表**，并给出**取样三条硬口径**：
   主体必须是叙述段（台词 ≤1/3）、挑常态段不挑高潮段、段里不许有工艺语言。
   另补第一人称特例：叙述人称为主角时"作者腔"与"主角叙述腔"合并，但**仍 ≠ 主角的对话腔**。
2. **§4 项目级覆盖示例**标注口径，并给出"立项时手上没成稿"的解法：
   先写 200-400 字试笔段（不必是正文，只要是想要的那支笔）。
3. **verify.py init 新增 #29c**（WARN 级，init 作用域）：
   - 缺 `配置/身份/作者.md` → WARN
   - 样本段仍是模板原文（含"取样三条硬口径"那几行）→ WARN
   - 样本段台词占比 >1/3 → WARN，并给出占比数字
   - 缺/过短（<100 字）→ WARN
   **只有真命中才发声**，有好样本时完全静默（这是 v2.1.2 第②例的教训）。
4. **为什么是 WARN 不是 FAIL**：样本只能由人提供，机器填不出来，硬 FAIL 会锁死立项。
5. selftest 新增 **S11（6 断言）**：10 场景 32 断言 → **11 场景 38 断言**。

## v2.1.3（2026-10-16 · 世界自动运行：world.md / timeline.md 由手改改为机器推进）

> 触发：主人一句「世界自动运行态呢？」——俯瞰身份矩阵时发现体系只覆盖了创作团队（作者/编剧/
> 编辑/读者/档案员），**世界本身没有写入机制**：world.md 的当前状态与地点状态机靠 S4 手改。

### 根因：手写两遍的地方必然对不上，而"漏了"门禁看不见

以前落库一条世界事件要写两遍：world.md【时间线大事记】+ timeline.md。
手写两遍的结果是滞后（懒得补）、漂移（两处不一致）、漏更（忘了写）。
**而"漏更"不产生任何可报错的东西**——门禁读不到那一行，也就无从报错。

### 做法：单一写入点 + 写入器/检查器配对

1. **Change Report 新增 WORLD-TICK 机器解析区**（§四，五行协议）
   `clock / place / env / loc / event`，竖线分段，字段名照抄。
   把原先散文的「四、时间线推进」「五、世界/规则变化」合掉，编号顺延。
2. **新脚本 `world_tick.py`**（写入器）：解析 WORLD-TICK → 分发到
   - `timeline.md`：事件行（章号去重，**时间线唯一真相源**）
   - `world.md`：当前状态（当前进度/主场景/已解锁地点/环境）+ 地点状态机 upsert
   默认 dry-run，`--apply` 写盘，**幂等**（同章重复跑不产生重复行）。
3. **settle 加「世界时钟」检查**（检查器）：world.md 当前进度章号 < 最新落库章号 = FAIL。
4. **world.md 删除【时间线大事记】**，改为指向 timeline.md 的指针——事件只写一处。

> **为什么不只加检查器**：只加检查 = 每章必 FAIL 且没人推得动；
> **为什么不只加写入器**：不跑也没人知道。两者必须配对，这是一条新铁律。

### 实测（注入式负向，不是"看着绿"）

```
推进前 settle → [FAIL] 世界时钟 — 世界时钟停在第0000章 < 最新第0001章
world_tick --apply → 9 项变更（timeline 1 / world 8）
推进后 settle → PASS 25 / WARN 0 / FAIL 0
第二次跑 → timeline「第0001章行已存在→覆盖」、地点走 update 分支（幂等成立）
```

### 踩到的坑（自修）

- **同一项同时输出 WARN 和 PASS**：老格式 world.md 走完 warn 又落到 check('OK')，
  两条自相矛盾的结论并列——比没有这项检查更糟。改为二选一，并写进 selftest 断言 S9.5。
- 缺 world.md 不重复判 FAIL（init 的「6 状态文件齐全」已覆盖），降级为带说明的 WARN。

### 迁移期口径

老项目 world.md 无【当前状态】区块 = 判不了滞后，只 WARN 提示（不炸现有项目）。
按 v2.1.3 模板补齐区块后该项自动转为可机器校验。

### 自测

`selftest_gates.py` 新增 S9（世界时钟 5 断言）+ S10（写入器↔检查器配对 6 断言），
共 **10 场景 32 断言**全通过（原 8 场景 21 断言）。

## v2.1.2（2026-10-16 · 外部审计复核：修三处门禁自我欺骗 + 统一状态文件口径）

### 三处"门禁自我欺骗"（都是复核时自己挖出来的，审计没提）

**① 测试项目建错了，门禁照样全绿。**
门禁约定 6 状态文件 = world/characters/hooks/objects/**relationships**/timeline，
自测骨架却写成了 `facts.md`。init 照样 PASS 5 / FAIL 0——
因为 init 只查目录存在 + world.md 实质内容，**不查 6 个文件各自是否齐全**；
settle 只校验它要用到的那几个，缺的文件它根本不去读，于是"缺文件" == "没有可报错的地方"。
→ 补 `verify` #29b：6 状态文件齐全（缺任一 = FAIL）+ 命名合规（别名 = WARN）。

**② 一条恒定假警报被当成"WARN 0"。**
上轮为让检查项在输出里可见写了 `else: warn('细纲台词越界', 'OK')`，
导致这项每次都出现在 WARN 列表里。**这比没检查更糟**——
真警报混在假警报里会一起被忽略（狼来了）。→ 删 else 分支，WARN 只在真命中时发声。

**③ `execution_mode` 检查挂错 scope，等于从没执行过。**
它早就存在，但挂在 `execution` scope 上，而每章实际跑的是 `settle`。
GPT 说"无 Python 降级依赖自觉、缺机器强制"——诊断对，根因却是**检查挂在没人跑的 scope**。
→ 抽出 `exec_mode_declared()`，execution 与 settle 双挂；声明行补进 `log-template.md` 决策摘要首行。

### 三套状态文件命名统一（治"外部审计分歧 = 内部不一致的镜像"）
