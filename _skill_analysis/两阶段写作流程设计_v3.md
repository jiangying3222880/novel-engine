# 两阶段写作流程设计 v3（骨架→血肉 · 最终版）

> 性质：v1.9.0 流程层核心改造方案（定稿）。基于 v2 + 三项最终拍板更新：
> ①骨架文件格式 = Markdown（非 YAML/JSON）②短篇也走细纲门 ③付费点检查移除（"小说写得好就行"，由断章位置自然覆盖）。

## 0. 结论先行

- **方向可行**：Ghostproof（beat sheet supremacy）、SegmentFault（不让 AI 决定剧情走向）、StoryWriter（outline→planning→writing 三 Agent）均验证。
- **T1 实测 7844 字 = "骨架没力度"的直接证据**：细纲给不出这节该干嘛 → 讲述者写个"高密度框架版"草草收场。
- **关键纠正**：现在的细纲是"标题式"（第一章相遇/第二章误会）= PPT 提纲 = 没力度。骨架必须是模板路由 + 四维约束 + 叙述形态。
- **文件格式**：骨架 = Markdown 结构化（用户拍板），非 YAML/JSON；机器校验能力由 runtime 校验器对 md 结构做解析（如存在性/字数/字段锚点）。

## 1. 骨架 = 模板路由 + 四维约束（Markdown）

### 1.1 骨架模板路由（技法库驱动）

| 项目类型 | 路由到的技法库骨架 |
|---------|-------------------|
| 憋压赘婿/窝囊流 | 憋压三段式引擎（情绪债务×兑现） |
| 都市悬疑/信息差 | 冲突链 + 信息三层错位（C-003） |
| 身份逆转/装逼打脸 | 身份逆转反转法 + 公开处刑引擎 |
| 长线成长流 | 多卷赌注升级 + 三线并行（C-105） |

> 骨架模板 = L2 技法层（可替换、按需装配、不污染）。编剧拿到卷纲后先路由选骨架模板，再往里填本章冲突。

### 1.2 细纲文件结构（Markdown 模板）

```markdown
# 章节细纲_第000X章.md

## 骨架模板
> 路由：〈技法库引擎名〉

## 冲突链（叙述形态）
- 主角想要什么：
- 谁拦他 / 拦的理由：
- 第一次怎么弄砸：
- 付出什么代价：

## 情绪弧
- 憋压层次：第 N 层 / 压什么
- 临界点（微光前奏，不是爽）：
- 爆发/收束点：

## 信息释放
- 本节新信息：
- 藏的（读者侧藏/反派侧藏/意识侧藏）：
- 钩子点（哪一秒给）：

## 声线要求
- 角色A：说话方式 / 第一反应 / 在意点
- 角色B：……

## 任务字数
- 节1（开场）：〈数字〉字
- 节2（蓄力）：〈数字〉字
- ……
```

**骨架有力度 = 叙述形态 + 删节断链**
- ✅ 叙述形态："林野发现老赵声音可疑 → 备份语音 → 设局"
- ❌ 流程图形态："目标→行动→阻力→选择→结果"
- ✅ 删掉任何一节，故事链条断掉 = 力度够
- ❌ 任何一节删掉不影响链条 = 注水骨架，打回

## 2. 流程角色与门禁（定稿）

### 2.1 角色流水线（仍 5 角色）

```
S1 骨架（编剧） → S2 血肉（讲述者·物理隔离） → S3 检验（编辑·双门禁） → S4 落库（档案员）
```

### 2.2 门禁执行者：检验角色兼任双门禁（不设第 6 角色）

| 门禁 | 时机 | 执行者 | 内容 |
|------|------|--------|------|
| **细纲门** | S1 产出后、S2 前 | 检验角色 | 力度检查 4 项（叙述形态/删节断链/冲突链完整/每节任务字数） |
| **正文门** | S2 产出后 | 检验角色 | 骨架逐节点对齐 + 双视角评估 + 遮名测试 |

> 排除项：编剧自检（自嗨不可靠）；编排层复核（带全规则会回流）；独立审计 agent（多一次调用+交接复杂化）。

### 2.3 双视角评估（读者 + 网文编辑，合并一份报告）

```
检验报告_第000X章.md
├─ 骨架逐节点核对（✅/❌ + 原文证据）
├─ 【读者视角】吸引力/憋压感/好奇心（读得下去吗）
├─ 【编辑视角】节奏/钩子密度/断章位置/爽点
├─ 遮名测试（声线进嘴？）
└─ 结论 + 打回方向（骨架问题→S1 / 表达问题→S2）
```

- 两次评估并行（一次调用内完成），不增加轮次
- 打回闭环 ≤2 轮，保留 Best Version（A-04）
- 规则不回写，只通过打回指令传递（A-14）
- **已移除**：付费点检查（用户拍板：小说写得好就行，断章位置自然覆盖）

### 2.4 落库

- 依据检验报告 + Change Report 更新 6 状态文件（A-07 原子提交）
- 滚动窗口：写第 N 章读 N-5~N+5 章骨架（B-02）
- 输入包（骨架文件 + 检验报告）落盘存档 = 隔离证据链（D-214）

## 3. 短篇 = 流水线复用 + 骨架简化 + 也走细纲门

**短篇不是"长篇加速版"，是"长篇去掉多层嵌套，只留单弧"。**

| | 长篇（单章级） | 短篇 |
|---|---|---|
| 骨架层级 | 卷弧嵌套章弧（多层） | 单情绪弧（单层） |
| 冲突链 | 多链并行（主线+支线+暗线） | 单链到底 |
| 情绪弧 | 每章一个憋压段，卷级累积 | 憋全场一次性爆发（皮筋式） |
| 检验重点 | 骨架对齐+连续性+商业性 | 憋到位+爆发有力+断在最高点 |
| 落库 | 6 状态文件+滚动窗口 | 不建项目/不落 truth（现有定位保留） |

**短篇流程（用户拍板：也走细纲门）**：
- S1 骨架：憋压三段式细纲（注水开场→蓄力→爆发），模板来自 `short-story-engines.md`，同样过细纲门
- S2 血肉：讲述者隔离写作（输入=短篇骨架）
- S3 检验：憋压到位/爆发有力/断在最高点（沿用现有 short-story 自检升级为报告形态）
- S4 落库：简化（不建 6 状态文件）

> 短篇不走细纲 = 回到"一次性写完整篇"的老路（实测 47% 成功率），所以细纲门对短篇同样必要。

## 4. 验证标准（v1.9.0 baseline）

- 同命题（《中秋》都市憋压赘婿）重跑
- **骨架力度验证**：S1 产出删节测试（删任一节链条是否断）
- **隔离验证**：S2 输入包原样落盘（证据链）
- **初稿对比**：新流程初稿 vs 7844 字（目标：单节 ≥ 1500 起步，向 2000 逼近）
- **AI 味盲评**：隔离前后同命题段落，用户盲评
