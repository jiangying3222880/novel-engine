> 性质：v1.9.0 流程层核心改造草案。基于 v1 讨论 + 用户拍板更新。
> 变更：①骨架模板路由化（技法库驱动）②门禁执行者=检验角色兼任 ③双视角评估合并报告 ④短篇=流水线复用+骨架简化。

## 0. 结论先行

- **方向可行**：Ghostproof（beat sheet supremacy）、SegmentFault（不让 AI 决定剧情走向）、StoryWriter（outline→planning→writing 三 Agent）均验证。
- **T1 实测 7844 字 = "骨架没力度"的直接证据**：细纲给不出这节该干嘛 → 讲述者写个"高密度框架版"草草收场。
- **关键纠正**：现在的细纲是"标题式"（第一章相遇/第二章误会）= PPT 提纲 = 没力度。骨架必须是四维约束 + 叙述形态。
- **骨架模板不是写死的单一格式**：从 `library/techniques/` 按题材/文风/篇幅路由（L2 技法层设计）。

## 1. 骨架 = 模板路由 + 四维约束

### 1.1 骨架模板路由（技法库驱动 · 新增）

| 项目类型 | 路由到的技法库骨架 |
|---------|-------------------|
| 憋压赘婿/窝囊流 | 憋压三段式引擎（情绪债务×兑现） |
| 都市悬疑/信息差 | 冲突链 + 信息三层错位（C-003） |
| 身份逆转/装逼打脸 | 身份逆转反转法 + 公开处刑引擎 |
| 长线成长流 | 多卷赌注升级 + 三线并行（C-105） |

> 骨架模板 = L2 技法层（可替换、按需装配、不污染）。编剧拿到卷纲后先路由选骨架模板，再往里填本章冲突。力度来自选对引擎，不是格式复杂度。

### 1.2 四维约束（骨架内容，叙述形态）

| 维度 | 要写什么 | 对应问题清单 |
|------|---------|-------------|
| 冲突链 | 主角想要什么 → 谁拦他 → 第一次怎么弄砸 → 付出什么代价 | E-005 / C-111 |
| 情绪弧 | 这一节的憋压层次：压什么、压到第几层、临界点在哪 | C-202 / C-205 |
| 信息释放 | 这节给读者什么新信息、藏什么、在哪一秒给（钩子点） | C-207 / C-401 |
| 声线要求 | 出场角色各自的说话方式/第一反应/在意点 | C-602 / A-11 |

**骨架有力度 = 叙述形态 + 删节断链**
- ✅ 叙述形态："林野发现老赵声音可疑 → 备份语音 → 设局"
- ❌ 流程图形态："目标→行动→阻力→选择→结果"
- ✅ 删掉任何一节，故事链条断掉 = 力度够
- ❌ 任何一节删掉不影响链条 = 注水骨架，打回

## 2. 流程角色与门禁（四项决策落点）

### 2.1 角色流水线（仍 5 角色，无新增）

```
S1 骨架（编剧） → S2 血肉（讲述者·物理隔离） → S3 检验（编辑·双门禁） → S4 落库（档案员）
```

### 2.2 门禁执行者（决策 2：检验角色兼任双门禁，不设第 6 角色）

| 门禁 | 时机 | 执行者 | 内容 |
|------|------|--------|------|
| **细纲门** | S1 产出后、S2 前 | 检验角色 | 力度检查 4 项（叙述形态/删节断链/冲突链完整/每节任务字数） |
| **正文门** | S2 产出后 | 检验角色 | 骨架逐节点对齐 + 双视角评估 + 遮名测试 |

> 理由：检验角色天然只加载"检查清单"不加载写作规则 = 物理隔离；同一执行者两道门口径统一；不增加额外 LLM 调用。
> 排除项：编剧自检（自嗨不可靠）；编排层复核（带全规则会回流）；独立审计 agent（多一次调用+交接复杂化）。

### 2.3 双视角评估（决策 3：读者 + 网文编辑，合并一份报告）

```
检验报告_第000X章.md
├─ 骨架逐节点核对（✅/❌ + 原文证据）
├─ 【读者视角】吸引力/憋压感/好奇心（读得下去吗）
├─ 【编辑视角】节奏/钩子密度/断章位置/付费点/爽点
├─ 遮名测试（声线进嘴？）
└─ 结论 + 打回方向（骨架问题→S1 / 表达问题→S2）
```

- 两次评估并行（一次调用内完成），不增加轮次
- 打回闭环 ≤2 轮，保留 Best Version（A-04）
- 规则不回写，只通过打回指令传递（A-14）

### 2.4 落库（决策不变 + 输入包存档）

- 依据检验报告 + Change Report 更新 6 状态文件（A-07 原子提交）
- 滚动窗口：写第 N 章读 N-5~N+5 章骨架（B-02）
- 输入包（骨架文件 + 检验报告）落盘存档 = 隔离证据链（D-214）

## 3. 短篇 = 流水线复用 + 骨架简化（决策 4）

**短篇不是"长篇加速版"（只快不行），是"长篇去掉多层嵌套，只留单弧"（结构不同）。**

| | 长篇（单章级） | 短篇 |
|---|---|---|
| 骨架层级 | 卷弧嵌套章弧（多层） | 单情绪弧（单层） |
| 冲突链 | 多链并行（主线+支线+暗线） | 单链到底 |
| 情绪弧 | 每章一个憋压段，卷级累积 | 憋全场一次性爆发（皮筋式） |
| 检验重点 | 骨架对齐+连续性+商业性 | 憋到位+爆发有力+断在最高点 |
| 落库 | 6 状态文件+滚动窗口 | 不建项目/不落 truth（现有定位保留） |

**短篇流程**：同一套 S1→S2→S3 流水线，骨架只用 3 段（注水开场→蓄力→爆发），模板来自 `short-story-engines.md`，S4 落库简化。
