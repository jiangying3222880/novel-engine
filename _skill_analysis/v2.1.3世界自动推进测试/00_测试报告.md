# v2.1.3 世界自动推进 · 实测报告（2026-10-16）

## 起因

主人一句「世界自动运行态呢？」——俯瞰身份矩阵时发现：体系把作者/编剧/编辑/读者/档案员
每个身份都分了两态，**但世界本身没有写入机制**。world.md 的当前状态与地点状态机
靠 S4 档案员读 Change Report 手改。

## 根因

一条世界事件要手写在两处：world.md【时间线大事记】+ timeline.md。
手写两遍的必然结果是滞后 / 漂移 / 漏更，而 **「漏更」不产生任何可报错的东西** ——
门禁读不到那一行，也就无从报错（与 v2.1.2 第①例「缺文件 = 没有可报错的地方」同源）。

## 落地

| 环节 | 做法 |
|------|------|
| 写入点 | Change Report 新增 **WORLD-TICK 机器解析区**（clock/place/env/loc/event 五行，竖线分段） |
| 写入器 | 新脚本 `ne-tools/runtime/world_tick.py`：解析 → 分发到 world.md（当前状态 + 地点状态机 upsert）与 timeline.md（事件行，章号去重）。默认 dry-run，`--apply` 写盘，幂等 |
| 检查器 | `verify.py --scope settle` 新增 **世界时钟**：world.md 当前进度章号 < 最新落库章号 = FAIL |
| 去重 | world.md 删除【时间线大事记】，改为指向 timeline.md 的指针——事件只写一处 |

> **写入器与检查器必须配对**：只加检查 = 每章必 FAIL 且没人推得动；只加写入器 = 不跑也没人知道。

## 实测过程

```
① 推进前 settle
   [FAIL] 世界时钟 — 世界时钟停在第0000章 < 最新第0001章（补 WORLD-TICK 后跑 world_tick.py --apply）
   → PASS 24 / WARN 0 / FAIL 1

② world_tick.py --apply（9 项变更）
   [~] timeline.md    第0001章行已存在→覆盖
   [~] world.md       当前进度→第 0001 章 / 周一 晚
   [~] world.md       主场景→十七楼总监办公区
   [+] world.md       已解锁地点 +大楼天台
   [~] world.md       天气→多云 ｜ 季节→秋 ｜ 特殊状态→无
   [~] world.md       update:十七楼总监办公区(intact→intact)
   [~] world.md       insert:大楼天台(intact)

③ 推进后 settle
   → PASS 25 / WARN 0 / FAIL 0

④ 幂等：第二次跑 → timeline 走 update 分支（不重复追加）、地点走 update（不重复插行）
```

`timeline.md` 用的是**老 3 列格式**（`| 章号 | 时间 | 事件 |`），脚本兼容并原格式追加，未破坏老项目。

## 门禁回归自测

`selftest_gates.py` 新增 2 场景 11 断言：

| 场景 | 断言要点 |
|------|---------|
| S9 世界时钟 | 时钟同步 PASS / 停旧章 FAIL / 缺当前进度行 FAIL / 老格式只 WARN **且不并列 PASS** |
| S10 写入器↔检查器 | 缺 WORLD-TICK 退出码 2 / 默认 dry-run / --apply 写盘 / 推进后 settle PASS / 重复跑幂等 |

→ **10 场景 32 断言全通过**（原 8 场景 21 断言）。

## 顺手修的两处假警报

1. **同一项同时输出 WARN 和 PASS**：老格式 world.md 走完 warn 又落到 check('OK')，
   两条自相矛盾的结论并列 —— 比没有这项检查更糟。改为二选一，并写进 S9.5 断言防复发。
2. **skill_lint 引用断链误报**：技能包是一个整体，`ne-memory` 里写 `relationships.md`
   指的是 `ne-setup/templates/truth/relationships.md`，此前被误判断链。
   修法：按 basename 在包内解析 + 行内 `<!-- link-exempt -->` 豁免历史异名。
   **负向验证**：注入 `不存在的假文件_xyz.md` 仍被抓（WARN 1 处），撤销后 WARN 0 —— 检查器没变瞎。
