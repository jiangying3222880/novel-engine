# v1.9.0 物理隔离改造方案 v2（吸收 DeepSeek 五点修正）

> 性质：改造执行蓝图。将"两阶段写作流程设计 v3"（骨架→血肉）映射到 novel-engine 现有文件结构。
> 基线：D 盘主仓 v1.8.0（commit 1e9d0ad），工作区干净。
> 变更：吸收 DeepSeek 五点修正——①三条硬指令不删改降级 ②细纲门硬软分层+节级打回 ③声线从角色卡透传 ④滚动窗口=N-5~N ⑤与 v1.8.0 批次覆盖关系明确；+ 新增"角色状态最小摘要"节。
> 关键判定：v1.8.0 的 execution-modes.md 产物链落盘机制（2.1 交接物）已是物理隔离的地基；缺的是 ①细纲标准化为产物文件 ②写作输入包=仅骨架 ③检验报告产物化。

## 0. 核心改造逻辑

```
v1.8.0（模拟隔离）                      v1.9.0（物理隔离 · multi 模式）
─────────────────                      ─────────────────
阶段①规划 → 规划清单（在会话内）         S1 骨架 → 细纲_第XXXX章.md（标准产物，落盘）
阶段②写作 → 三条硬指令模拟隔离           S2 血肉 → 写作输入包 = 仅细纲文件（物理最小）
阶段③自检 → 自检报告（会话内）           S3 检验 → 检验报告_第XXXX章.md（双视角产物）
阶段④润色 → 精修稿（会话内）             （并入 S3 打回分支，不再独立阶段）
阶段⑤落库 → Change Report               S4 落库 → 原子提交 + 输入包存档 + 滚动窗口
```

**一句话**：把"会话内的角色切换"改为"文件系统上的角色交接"——每个角色只读自己的标准输入、只写自己的标准产物，中间没有会话记忆残留。

**⚠️ 物理隔离适用条件（DeepSeek 隐患一修正）**：
- **multi 模式 = 物理隔离**：讲述者 Agent 在独立子窗口，物理上看不到规则文本/状态文件/技法库，只读细纲文件
- **single 模式 = 模拟隔离**：同一窗口内，三条硬指令（角色重锚定/输入最小化/禁读清单）**保留**，标注为"single 模式专用降级方案"
- 隔离证据链（D-214）措辞修正：single 模式下的落盘证明改称"**降级声明记录**"——诚实说明只能做到声明级最小化，做不到物理隔离

## 3. 关键机制设计

### 3.1 细纲门（S1→S2 前置 · 硬软分层）

**第一道：硬性结构检查**（verify.py 可校验，不是语义判断）：
- [ ] 每节都写了"任务字数"（数字非空）
- [ ] 冲突链四节点（想要/阻拦/弄砸/代价）都有内容
- [ ] 声线要求覆盖所有出场角色，且标注来源（见 3.3）
- [ ] 角色状态最小摘要存在

**第二道：软性删节推理**（检验 Agent 做，必须写推理过程）：
- 要求输出"**如果删掉这一节，下一节会缺什么**"的具体推理，而不是只给"力度够/不够"结论
- 有推理过程的判断比只有结论的判断可靠

**节级打回（DeepSeek 隐患二修正）**：不是整章重写——只打回有问题的节，打回指令标注"细纲_第XXXX章.md 第 3 节：删节推理不成立（原因一句话）"，编剧只改该节。

### 3.2 写作输入包（S2 物理最小 · multi）

讲述者 Agent 启动时**只读**：
```
故事/元数据/细纲_第XXXX章.md（唯一强制输入）
novel-config.json（仅 target_word_count + body_dir）
```
**禁止读取**：6 状态文件、writing-guide.md、anti-ai.md、self-review.md、技法库全文。声线信息已由编剧压缩进细纲"声线要求"节（A-11）。

### 3.3 声线透传（DeepSeek 隐患三修正 · 从角色卡引用不自由发挥）

细纲"声线要求"节**不是编剧自由发挥，而是从 `characters.md` 角色卡提取**，每行标注来源：
```markdown
## 声线要求
- 林野｜来源：characters.md#林野，本章无变化
- 老赵｜来源：characters.md#老赵，本章新增：在老赵面前刻意放慢语速（对林野的试探戒备）
```
- 无变化 → 标注"本章无变化"即可（讲述者按基线声线写）
- 有变化 → 标注"本章新增" + 一句具体变化
- 这样讲述者只读细纲，声线信息从角色卡透传，跨章不漂移

### 3.4 角色状态最小摘要（DeepSeek 额外建议 · 新增节）

解决"讲述者不读状态文件但需要知道角色知识边界"的矛盾：
```markdown
## 角色状态最小摘要
- 林野：知道老赵撒谎；不知道陈默是卧底；对警方戒备
- 老赵：以为林野不知道自己的身份；实际已知林野在查
```
由编剧从 6 状态文件提取，压缩成一行/角色。讲述者只读这一节，就知道"谁该知道什么"——**禁止不等于不需要，需要的信息由上游压缩透传**。

### 3.5 滚动窗口（DeepSeek 隐患四修正 · N-5~N 只读历史）

- 明确定义为 **N-5~N**（只读历史细纲），**不含未来章节**（N+1~N+5 尚不存在）
- 历史细纲读取最小化：**只读"冲突链"和"信息释放"两节**，不读全文（这两节是跨章连续性最关键的）
- 宿主支持时：历史细纲摘要作为独立产物（`故事/元数据/细纲摘要_卷X.md`），编剧只读摘要
- 跨会话续写（F-01）：S1 强制重读最近 N 章细纲摘要+状态摘要

### 3.6 检验报告（S3 双视角）

```
检验报告_第XXXX章.md
├─ 骨架逐节点核对（细纲每节 → 正文证据，✅/❌ + excerpt）
├─ 【读者视角】吸引力/憋压感/好奇心（读得下去吗）
├─ 【编辑视角】节奏/钩子密度/断章位置/爽点
├─ 遮名测试（声线进嘴？）
└─ 结论 + 打回方向（骨架问题→S1 节级 / 表达问题→S2）
```
- 双视角并行（一次调用内完成）
- 打回闭环 ≤2 轮，保留 Best Version
- 规则不回写（A-14）

### 3.7 S4 落库原子化

- 新增"暂存 → 校验 → 提交 → 回滚"四步（A-07）：Change Report 先落暂存区 → verify 校验 → 通过后批量更新 6 状态 → 失败保留旧状态
- 输入包存档：`故事/日志/第XXXX章.md` 附"本章输入包=细纲_第XXXX章.md + 检验报告_第XXXX章.md"链接（multi=隔离证据链 / single=降级声明记录）

### 3.8 打回闭环

```
S3 检验 → 骨架问题（链条断/没力度）→ 节级虚线回 S1（编剧重设计该节）
        → 表达问题（写得太差/声线崩）→ 回 S2（讲述者重写）
        → 通过 → S4 落库
```
- 打回指令 = 检验报告文件名 + 打回原因（一句），**不携带规则/修改建议文本**（防规则回写，A-14）
- 上限 2 轮，保留 Best Version（A-04）

## 6. 风险与边界

| 风险 | 缓解 |
|------|------|
| 宿主无子 Agent 能力（A-01） | single 降级：三条硬指令 + 输入包最小化 + 降级声明记录；产物链不降级 |
| 细纲质量不稳（垃圾进垃圾出） | 细纲门硬软分层：结构硬检 + 删节推理软检（要求写推理过程）；节级打回 ≤2 轮 |
| 检验 Agent 评估无标准 | 双视角模板固定维度 + 证据 excerpt 强制 + 删节推理必须写"下一节缺什么" |
| 状态文件膨胀（B-01） | 滚动窗口只读 N-5~N 且只读冲突链+信息释放两节；卷末归档（后续版本） |
| 声线跨章漂移 | 声线要求从 characters.md 透传（标注来源），非自由发挥 |
