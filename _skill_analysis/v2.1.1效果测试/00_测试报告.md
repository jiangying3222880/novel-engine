## 四、越界实测：三条新硬约束，只有一条真有闸

这是本次测试最有价值的发现。故意做了越界样本，看门禁抓不抓：

| 越界类型 | 注入方式 | 门禁反应 | 有闸吗 |
|---|---|---|---|
| 编辑无证据判定 | 抽掉报告 §6 evidence_ids | **FAIL 1** | ✅ 有（#8 已存在） |
| 编剧细纲写台词 | 细纲注入 2 句对话 | PASS（**没抓到**） | ❌ 无 |
| 读者首读给解法 | 无法机器注入 | — | ❌ 无（纯纪律） |
| 档案员检索态改文件 | 无法机器注入 | — | ❌ 无（纯纪律） |

**即：四条纪律里只有编辑那条真正被机器守住**，其余三条靠自觉。

### 已补：细纲台词越界检查（WARN 级）

在 `verify.py` settle 新增。开发过程中踩了两个坑（都靠注入式负向测试才发现）：

1. **第一版漏抓** —— 正则只认中文弯引号/直角引号，注入用的是 ASCII 直引号。
2. **第二版误报** —— `"她要么是装的，要么真不记得"` 是人物判断不是台词，被判为越界。

最终规则：**引号前必须是说话动词**（说/道/问/答/喊/回/骂/叫）+ 引号内容 ≥5 字，
且排除上下文含"必须原样出现"的逐字内容。

- 正向（合规细纲）→ `细纲台词越界 — OK`（零误报）
- 负向（注入 2 句台词）→ 精确报出「我们不熟。」「第三页那个数也不对。」
- selftest 21 断言不受影响

## 五、测试中发现的其他三个问题

1. **检验报告模板契约没写进编辑档案**。我第一版报告用了自由格式 `evidence:`，
   门禁直接 FAIL——正确字段名是 **`evidence_ids`**，且必须有 Q1-Q7 八个小节。
   编辑档案里只写了"判定要指回文本"，**没写契约字段名**，写报告的人（AI）会天然写错。

2. **`novel-config.json` 模板缺 v2.1 新增字段**。`platform` / `style_card` /
   `style_fingerprint` / `genre_tags` 写进了文档，但**没进 `ne-setup/templates/novel-config.json`**——
   复制模板建项目时这些字段不存在，风格卡无从注入。

3. **timeline.md 必须是表格**（`| 0001 | … |`），写成 `- 第0001章：…` 会被判"时间线滞后" FAIL。
   这个格式要求在任何身份档案里都没提。

> 问题 1、2 已修；问题 3 待写进档案。

## 六、结论

**体系是能跑通的**：一条完整链路产出合规，门禁 PASS 23 / FAIL 0，指标与 B 版一致（说明风格稳定）。

**但"细分两态"目前是纪律，不是机制**：五个身份里只有编辑（evidence_ids）和作者（部分）
有机器约束，编剧/读者/档案员三条靠自觉。这次补上了编剧那条，读者和档案员仍是纯纪律。

# 七、外部审计复核（2026-10-16 · 本篇结论的自我修正）

DeepSeek 与 GPT 各出了一份 v2.1.1 审计（原文存 `../外部审计/`）。
复核时把它们当线索去查仓库，结果**挖出三个比审计里任何一条都硬的问题，
而且它们共同指向同一件事：我上一轮报的"PASS"是有水分的**。

## 7.1 水分一：测试项目本身建错了，门禁照样全绿

门禁约定 6 状态文件 = `world / characters / hooks / objects / relationships / timeline`。
我搭测试骨架时写成了 `facts.md`（顶替 relationships.md）。

**init 照样 PASS 5 / FAIL 0。**

原因：`init` 只查目录存在 + world.md 实质内容，**不查 6 个文件各自是否齐全**；
`settle` 只校验它要用到的那几个（timeline/hooks/objects），缺的文件它根本不去读——
**"缺文件" == "没有可报错的地方"**，于是静默通过。

→ 已补 `init` 检查 #29b：6 状态文件齐全 + 命名合规（别名转 WARN）。
现在同一个样本：`[FAIL] 缺状态文件：relationships.md` + `[WARN] facts.md→应为 relationships.md`。

## 7.2 水分二：一条恒定假警报被我当成"PASS 0 WARN"

上轮为让检查项在输出里可见，写了 `else: warn('细纲台词越界', 'OK')`。
结果这项**每次都出现在 WARN 列表里**，输出长这样：

```
[WARN] 细纲台词越界  — OK
```

当时我报告"settle PASS 23 / WARN 0"，实际这句恒在。
**这比没有检查更糟**——真警报混在假警报里会一起被忽略（狼来了）。

→ 已删 else 分支。WARN 项只在真命中时发声。

## 7.3 水分三：一条检查挂错了 scope，等于从没执行过

`execution_mode` 声明检查（#9b）早就存在，但它挂在 `execution` scope 上，
而**每章实际跑的是 `settle`**——等于这条从没真正生效。

GPT 说"无 Python 环境时降级依赖 Agent 自觉，缺乏机器强制"——诊断对，
但根因不是"没写检查"，是**检查挂在了没人跑的 scope 上**。

→ 抽出 `exec_mode_declared()`，`execution` 与 `settle` 双挂。
现在没写声明的日志：`[FAIL] 最新日志(第0001章.md)缺 execution_mode 声明行（降级未留痕）`。
同时把声明行补进 `log-template.md` 决策摘要首行（模板没有它，AI 就不会写）。

## 7.4 意外收获：三套状态文件命名，LLM 的"幻觉"其实是仓库的镜像

两份审计列出的 6 状态文件清单不一样：

| 来源 | 清单 |
|---|---|
| `ne-setup/templates/truth/`（有模板） | world / characters / hooks / objects / **relationships** / timeline |
| `ne-memory/SKILL.md` | world / characters / **facts** / objects / hooks / timeline |
| `ne-review/consistency-checklist.md` + `check_text.py` | 引用 `真相/**facts**.md` |
| `ne-memory/SKILL.md`（旧）+ skill_lint 旧白名单 | `**worldview**.md` |

DeepSeek 报 worldview 系、GPT 没细列——**看起来像模型幻觉，实际是仓库自己在自相矛盾**，
它们各自读到了不同文件。这是我第一次看到"外部审计的分歧 = 内部不一致的镜像"。

→ 统一到有模板支撑的那套。`facts`（已确立事实）职能并入 `objects.md`
（关键物品/资源 + 数值与约定台账），不单独立第 7 个文件（响应"别再加东西"）。
新增 `skill_lint` 检查 15「状态文件命名统一」，含 `truth-naming-exempt` 豁免标记。

## 7.5 核实结论：两条属实、两条不准

| 审计说法 | 判定 |
|---|---|
| README 末尾写 v1.9.1.3（与顶部 v2.1.1 不一致） | ✅ 属实，且 v2.0/v2.1 根本没进版本表 |
| 无 Python 环境降级缺机器强制 | ⚠️ 部分属实（检查有，但挂错 scope） |
| 6 状态文件 = world/characters/**facts**/objects/hooks/timeline | ❌ 不准（facts 无模板、无门禁） |
| 每个文件维护 5 通用字段 | ⚠️ 夸大：3 必填（status/visibility/source_chapter）+ 2 预留 |
| verify 五级 scope | ❌ 实为 8 个（+all），对外文档只说 4 个 |
| 素材 158 文件 | ⚠️ 实为 199 |
| GitHub 仓库 404 / 读取失败 | ❌ 仓库是 public 且 200 可读，是它们那侧网络问题（与我们 push 遇到的 502 同类） |
| C-003 落地不清晰 | ⚠️ 部分属实：`narrative-kernel.md` 有专节，但细纲模板没有三层对齐字段 |

最后一条已补：细纲模板 §4 加「三层对齐（C-003）」小表（事实层/角色层/读者层）。

## 7.6 修正后的结论

上轮的"PASS 23 / FAIL 0 / WARN 0"应更正为：

> **流程能跑通，但那次门禁结果不成立**——样本本身缺一个状态文件、
> 有一条恒定假警报、有一条该生效的检查从没跑过。
> 门禁的"全绿"此前证明的是"我构造的样本满足门禁检查的那些条件"，
> 而门禁当时连"6 个文件是否齐全"都没查。

这正是 GPT 那句"门禁通过 ≠ 小说好看"在工程层的对应物：
**门禁通过也不等于门禁覆盖到了该覆盖的地方。**
