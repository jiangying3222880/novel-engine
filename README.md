# Novel Engine v1.9.1.1

工业级网文写作 Skill：纯 Markdown 状态机（主）+ 检索运行时（runtime/，BM25+FTS 已落地，ZVEC 可选增强）。**技能只存模板，项目存内容。**整个系统**仅 `runtime/` 目录一处跑 Python**（内含 9 个脚本，其余全纯 Markdown；脚本清单见 `runtime/_README.md`）。

> ⚠️ 本文档为对外说明（安装 / FAQ）。**助手执行路由以 `SKILL.md` 为准，全文件地图以 `routes/index.md` 为准**（唯一真相源）。

## 快速使用

### 1. 安装为技能

将 `novel-engine/` 整个目录复制到助手的技能目录（如豆包的 `.user_skills/novel-engine/`），保持目录名与 `SKILL.md` 的 `name` 一致。

**验证安装**：对助手说 "写个短故事"，能进入短篇模式即安装成功；再试 "开新书" 进入长篇小说初始化。

### 2. 开始创作

1. 对 Agent 说 "开新书" 或 "导入已有项目"，进入阶段⓪初始化
2. （推荐）选 1-3 本对标书，Agent 自动拆解建立项目素材池（两阶段：快速预览→深度拆解）
3. 说 "写第 1 章" 启动 S1-S4 流水线（编剧细纲 → 讲述者正文 → 检验打回 → 落库）
4. 新角色首次登场时，Agent 自动按模板建立基线档案

**短故事单篇**：说 "写个短故事" / "抖音推文风" → 三段式单情绪弧憋压爆发，按节分单元生成，不建项目。节奏原理见 `references/short-story.md`，文梗选型见 `references/short-story-engines.md`。

**外包写作**：说 "这章外包" / "整本书走外包模式" → S1 骨架照跑后自动编译自包含提示词，贴入任意网页 chat 写作，正文贴回后走 S3 检验（含表达打回）→ S4 落库。流程见 `references/chat-outsource.md`。

### 3. Python 依赖说明

> **核心结论**：**核心写作不依赖 Python**（读文档、规划、写作、自检、润色全可手动执行）；但**流程门禁 / 检索索引 / 文档同步需要 Python**——未安装时门禁**跳过并在流程日志显式标注"手动校验降级"**，不静默假装通过。

| 功能 | 是否需要 Python | 未装 Python 时 |
|------|--------------|---------------|
| 技法/题材/流程/去AI味/自检文档 | ❌ 不需要 | 直接阅读 Markdown 手动执行 |
| **verify.py 流程门禁** | ✅ 需要（流程层硬门禁） | 跳过，**流程日志标注"手动校验降级"** |
| **bm25_fts.py 检索索引** | ✅ 需要 | 跳过索引，写作/落库照常 |
| **doc_sync.py 文档同步** | ✅ 需要（维护者用） | 跳过（仅技能维护者受影响） |
| check_text.py 词级检测 | ✅ 需要 | 手动对照词级信号检查 |

**未装 Python 时的规则**：
1. 写作流程照常（S1-S4 全部手动执行）
2. **门禁降级必须显式声明**：在 `故事/日志/第000X章.md` 写一行 `execution_mode=no_python，verify.py 跳过，手动校验：目录结构/命名/真相防污染已人工核对`
3. 降级只改变校验手段，**不减少交付物**

**ZVEC 检索**（可选增强）：仅当启用 ZVEC 混合检索时才需 `pip install -r runtime/requirements.txt`；不装时 `index.py`/`query.py` **自动回退 BM25+FTS**，功能不中断。

## 常见问题 FAQ

**Q：不装 Python 能用吗？**
能，写作功能照常。未装时门禁跳过并在流程日志**显式标注"手动校验降级"**，不静默假装通过（见上）。

**Q：`verify.py` / `doc_sync.py` 是干嘛的？报错要紧吗？**
- `verify.py` 是**流程门禁**：每轮交付前自动检查项目完整性，报错 = 流程未走完，应停下修正而非硬交付。
- `doc_sync.py` 是**说明文档同步**：修改技能文件后自动刷新各目录 `_README.md` 清单。这俩是给助手/维护者用的，用户无需手动运行。

**Q：怎么在 Obsidian 看角色 / 世界观 / 伏笔 / 章节图谱？**
- 项目生成后，把项目根 **`叙事总览/` 整个目录作为库（Vault）** 加入 Obsidian（或任意支持 `[[ ]]` 双链的 Markdown 工具）。
- **必须整目录导入、同库**：总览页（`00`–`05`）与原子卡片靠双链互相指向，只有放在同一库才能解析成连线。
- 双链由落库联动**自动生成**，你无需手动补链。总览是只读展示：不要手改，也别在库外另建同名笔记。

**Q：短故事和长篇能混用吗？**
能。它们走两套流程，互不干扰。短故事不建项目，长篇用项目状态管理。

**Q：遇到问题去哪看？**
- 助手行为异常 → 看 `routes/index.md`（文件地图）+ `SKILL.md`（路由）。
- 想了解设计理念 → 看本 README。
- 想排查检索 → 看 `runtime/bm25_fts.py` 头部用法说明与 `references/retrieval.md`。
