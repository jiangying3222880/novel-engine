# Novel Engine v1.7

工业级网文写作 Skill：纯 Markdown 状态机（主）+ 检索运行时（runtime/，BM25+FTS 已落地，ZVEC 可选增强）。**技能只存模板，项目存内容。**整个系统**仅 `runtime/` 目录一处跑 Python**（内含 9 个脚本，其余全纯 Markdown；脚本清单见 `runtime/_README.md`）。

> ⚠️ 本文档为对外说明（安装 / 设计 / FAQ）。**助手执行路由以 `SKILL.md` 为准，全文件地图以 `routes/index.md` 为准**（唯一真相源）。

## 快速使用

> 👉 安装 / 上手 / FAQ 见下文：`安装依赖` → `安装为技能` → `目录结构总览` → `常见问题 FAQ`。本 README 是唯一对外说明。

### 0. 安装依赖（可选，仅 ZVEC 向量检索需要）

> **纯 py 核心依赖（jieba / pypinyin / pyyaml，检索分词用）已离线 vendored 到 `runtime/deps/`**，脚本自动加载，clone 即用、无需安装。默认 BM25 词法检索零依赖。仅当你想启用 ZVEC 检索（BM25 + 实验性词袋向量混合）时才执行：

```bash
pip install -r runtime/requirements.txt
```

> 不装也能写（纯写作不依赖 Python）；装了才有"检索"功能。ZVEC（BM25 + 实验性词袋向量混合）为可选增强，不装时 `index.py`/`query.py` **自动回退 BM25+FTS**，功能不中断。

### 0.5 Python 依赖说明（是否必须 · v1.8 口径统一）

> **核心结论（v1.8 统一口径，消除"可选/必跑"自相矛盾）**：**核心写作不依赖 Python**（读文档、规划、写作、自检、润色全可手动执行）；但**流程门禁 / 检索索引 / 文档同步需要 Python**——未安装时门禁**跳过并在流程日志显式标注"手动校验降级"**，不静默假装通过。写作能力不受影响，只是少一层机器校验。

| 功能 | 是否需要Python | 未装 Python 时 |
|------|--------------|---------------|
| 技法/题材/流程/去AI味/自检文档 | ❌ 不需要 | 直接阅读 Markdown 手动执行 |
| **verify.py 流程门禁** | ✅ 需要（流程层硬门禁） | 跳过，**流程日志标注"手动校验降级"**——不静默假装通过 |
| **bm25_fts.py 检索索引** | ✅ 需要 | 跳过索引，写作/落库照常（少检索能力） |
| **doc_sync.py 文档同步** | ✅ 需要（维护者用） | 跳过（仅技能维护者受影响） |
| check_text.py 词级检测 | ✅ 需要 | 手动对照词级信号检查 |

**未装 Python 时的规则（v1.8）**：
1. 写作流程照常（规划→写作→自检→润色→落库，全部手动执行）
2. **门禁降级必须显式声明**：verify.py 无法运行时，在 `故事/日志/第000X章.md` 写一行 `execution_mode=no_python，verify.py 跳过，手动校验：目录结构/命名/真相防污染已人工核对`——不允许跳过且不声明
3. 降级只改变校验手段，**不减少交付物**（正文/自检报告/Change Report/6状态更新一个不少）

**有 Python 时的额外好处**：机器校验替代人工自觉（verify.py 确保流程不走偏）、自动词级 AI 味检测（check_text.py --strict）、BM25 全文检索（快速定位章节/角色/物品）。

> 建议：新手或团队协作时安装 Python 以确保流程规范；单人使用且信任助手自觉时可不装，但必须按上述规则做显式降级声明。

### 1. 安装为技能

将 `novel-engine/` 整个目录复制到助手的技能目录（如豆包的 `.user_skills/novel-engine/`），保持目录名与 `SKILL.md` 的 `name` 一致。

**验证安装**：对助手说 "写个短故事"，能进入短篇模式即安装成功；再试 "开新书" 进入长篇小说初始化。

2. 对 Agent 说 "开新书" 或 "导入已有项目"，进入阶段⓪初始化

3. （推荐）选 1-3 本对标书，Agent 自动拆解建立项目素材池（两阶段：快速预览→深度拆解）

4. 说 "写第 1 章" 启动五阶段 SOP

5. 新角色首次登场时，Agent 自动按模板建立基线档案

**短故事单篇**：说 "写个短故事" / "抖音推文风" → 三段式单情绪弧憋压爆发（高压注水开场 → 憋压蓄力 → 大坝决堤），按节分单元生成，**写前必填驱动标注 4 字段**（制造什么期待 / 第几段引爆 / 憋到什么程度给 / 读者翻页动力），不建项目，见 `references/short-story.md`；题材/文梗选型见 `references/short-story-engines.md`（六引擎：情绪债务×兑现）。

**外包写作（提示词组装）**：说 "这章外包" / "整本书走外包模式" → 阶段①照跑后，技能自动读 6 状态文件 + 规划清单 + 作者身份，编译一份**自包含最终提示词**（含身份/状态/目标/手法/防剧透/字数验收），贴入任意网页 chat 写作，正文贴回后继续阶段③自检 → ④去AI味（必须跑满）→ ⑤落库。模板见 `templates/outsource-prompt.md`，流程见 `references/chat-outsource.md`。

## 目录结构总览

```
novel-engine/
├── SKILL.md              ← 技能入口（助手读取，自动识别）
├── README.md             ← 本文件（项目说明 + 安装 + FAQ）
├── routes/index.md       ← 路由台账：所有文件的"地图"（唯一真相源）
├── references/           ← 方法库（规划/写作/自检/反AI味/落库…+ 短故事）
├── library/              ← 用户级素材库（题材风格包/技巧/平台/身份…）
├── templates/            ← 模板（配置/章节/角色/素材池/短故事骨架…）
├── runtime/              ← Python 检索运行时（可选，见安装）
└── story/                ← 项目结构示意（仅示意，实际项目另建）
```

- **装好即用**：`SKILL.md` + `references/` + `templates/` + `library/` + `routes/` 都是只读成品。
- **可扩展**：`library/` 可放入你自己积累的题材包/技巧。
- **运行时生成**：`runtime/` 会在你建项目时自动往**项目目录**写索引（如 `故事/索引/bm25/`），不影响技能本体。
- 各目录 `_README.md` 是**给助手（机器）的导航**：含人工语义说明（定位/上游/使用引导/下游）+ 自动文件清单（由 `runtime/doc_sync.py` 维护）。改技能文件后运行 `python runtime/doc_sync.py update` 刷新清单。

## 五阶段工作流



```
规划(身份路由+细纲一致性+参考素材) → 写作(主角主动表达节点) → 举证自检(读者×编辑双通道) → 反AI味润色(成因层诊断+Prompt Defense) → 落库(Change Report+6状态+meta+日志+BM25/FTS索引)
```

每个阶段只读必要的参考文件，产出明确的交付物，阶段间不传递历史报错。

## 分层架构



* **技能层（通用）**：写作方法、模板、工作流 SOP — 写在 Skill 文件里，跨项目复用

* **项目层（每本书）**：故事/真相/（状态）+ 素材池/（素材池）+ 设定 / + 大纲 / + 正文 / — 每个项目独立

* **章节层（动态）**：声线章态、规划清单 — 阶段①输出里，当章用完即弃

## 素材池（素材池/）

池子是 **Agent 自动拆解对标书的产物**，不是凭空建的，也不是用户手动填的。空池子没有价值。



| 池子                      | 内容                          | 用途         |
| ----------------------- | --------------------------- | ---------- |
| `author_dna/`           | 作者写作习惯（文风定位 / 句式 / 节奏 / 词汇） | 风格校准       |
| `planner/`              | 卷结构 / 伏笔编排 / 情绪曲线 / 节奏统计    | 节奏校准       |
| `unit/`                 | 事件单元（情绪标记 + 节奏类型 + 完整事件链）   | 同类事件参考     |
| `reference/techniques/` | 8 大写作技巧方法论                  | 知道 "怎么写"   |
| `reference/samples/`    | 精选段落（按 5 条标准筛选入池）           | 看 "别人怎么落地" |
| `knowledge/`            | 事实知识（历史 / 医学 / 军事等）         | 专业场景查证     |

**拆解机制：**



* **谁来拆**：Agent 自动拆，用户只需提供对标书

* **怎么拆**：两阶段 —— 快速预览（前 3 章 + 整体结构）→ 用户确认 → 深度拆解（按档位全量）

* **判断标准**：Reference 入池需通过 5 条非 AI 味标准（≥4 条才入池）

* **每本书独立建池**：随项目创建，随项目归档，不跨书复用

**入池原则**：只放对标书拆解的高质量内容，不放自己的稿件（质量上限低于对标书，入池反而拉低水平）。

## 常见问题 FAQ

**Q：不装 Python 能用吗？**
能，写作功能照常。**v1.8 口径**：核心写作不依赖 Python；但流程门禁（verify.py）/检索索引（bm25_fts.py）/文档同步（doc_sync.py）需要 Python——未装时门禁跳过并在流程日志**显式标注"手动校验降级"**，不静默假装通过。不装只是少机器校验层，不减少任何交付物（见 §0.5）。

**Q：`verify.py` / `doc_sync.py` 是干嘛的？报错要紧吗？**
- `verify.py` 是**流程门禁**：助手每轮交付前自动检查项目完整性，报错 = 流程未走完，助手应停下修正而非硬交付。
- `doc_sync.py` 是**说明文档同步**：修改技能文件后自动刷新各目录 `_README.md` 清单。这俩是给助手/维护者用的，你无需手动运行。

**Q：ZVEC 是什么？必须装吗？**
可选增强。ZVEC 集成"词法 BM25 + 实验性词袋向量"两路混合召回，比纯 BM25 多一路近似召回，但要额外装 SDK、索引更大。⚠️ 注意：当前 dense 向量是**本地 jieba 词袋向量（实验性，非语义 embedding）**，`references/retrieval.md` 中的 bge-small-zh 语义 embedding 为**预留项、尚未接入**。不装 zvec 时自动回退 BM25+FTS，功能不中断。

**Q：为什么有的文件名带 `故事/真相`、`故事/元数据` 这种中文路径？**
技能约定项目目录**统一中文命名**（协议文件名保持英文，如 `chapter_0001.md`）。项目建在技能目录之外，与技能本体隔离。

**Q：怎么在 Obsidian 看角色 / 世界观 / 伏笔 / 章节图谱？**
- 项目生成后，把项目根 **`叙事总览/` 整个目录作为库（Vault）** 加入 Obsidian（或任意支持 `[[ ]]` 双链的 Markdown 工具）。
- **必须整目录导入、同库**：总览页（`00`–`05`）与原子卡片（角色卡 / 世界观卡 / 伏笔卡 / 章节卡）靠双链互相指向，只有放在同一库才能解析成连线。只零散拖入单个文件，图谱会分裂、出现"孤立 / 重复"节点（看到 `00_作品总览 1` 这类名字，就是库外另建了同名副本）。
- 双链由阶段⑤落库联动**自动生成**（单向源于真相），你无需手动补链。总览是只读展示：不要手改总览或卡片、也别在库外另建同名笔记——下一轮落库会覆盖手动改动，且会破坏"单向源于真相"的防污染隔离。

**Q：短故事和长篇能混用吗？**
能。它们走两套流程，互不干扰。短故事不建项目，长篇用项目状态管理。

**Q：遇到问题去哪看？**
- 助手行为异常 → 看 `routes/index.md`（文件地图）+ `SKILL.md`（三铁律/五阶段）。
- 想了解设计理念 → 看本 README。
- 想排查检索 → 看 `runtime/bm25_fts.py` 头部的用法说明与 `references/retrieval.md`。
