工业级网文写作 Skill：纯 Markdown 状态机（主）+ 检索运行时（
untime/，BM25+FTS 已落地，ZVEC 规划中，唯一 Python 部件）。**技能只存模板，项目存内容。**

## 解决什么问题

| 痛点 | 本引擎方案 |
|------|-----------|
| AI 写作呆板 | 去硬约束，改示范驱动（Few-shot）；反 AI 味从黑名单重构为质感标杆 |
| Agent 跳读/只读一半 | 单文件 ≤8KB，单次强制加载 ≤12KB，文件头加"后果提示" |
| Agent 不遵守约束 | 3 条铁律（底线）+ 其余全部降为 Guide；自检强制 evidence_ids 证据链 |
| 假自检 | 4 问必须标注原文片段，无证据的"通过"判定无效 |
| 乒乓球式短句/装酷感 | 对话不对称三原则 + 双层声线系统 |
| 不敢留白/解释腔 | 冰山法则（默认读者看过同类作品，只写物理结果不写原理） |
| 角色 OCC（出戏） | 基线档案（永久）+ 章态（每章动态），章态必须落在基线情绪光谱内 |
| 记忆漂移/前后矛盾 | story/truth/ 6文件状态中心（+objects/timeline），Change Report 驱动更新 |
| 检索靠全文扫描 | ZVEC 混合检索（dense+BM25+防剧透+知情权过滤），章节 YAML 迁 story/meta 供索引 |
| 身份单一 | 作者×编剧×编辑×读者身份路由，市场调查三档（快速/标准/深度） |
| AI 味复发 | 成因层诊断 7 层 + AI 味指数五档 + Prompt Defense 防诱导 |
| 长篇失控 | Obsidian 叙事总览（角色/世界观/伏笔/章节地图/关系网）+ 每章流程日志 |
| 风格漂移 | 对标书拆解素材池（pools/），Author DNA 风格锚点 + 高质量样本参考 |
| 对标书拆解靠人工 | Agent 自动拆解（两阶段：快速预览→深度），带判断标准筛选入池 |

## 快速使用

1. 将 `novel-engine-v1/` 整个目录安装为技能
2. 对 Agent 说"开新书"或"导入已有项目"，进入阶段⓪初始化
3. （推荐）选 1-3 本对标书，Agent 自动拆解建立项目素材池（两阶段：快速预览→深度拆解）
4. 说"写第1章"启动五阶段 SOP
5. 新角色首次登场时，Agent 自动按模板建立基线档案

## 五阶段工作流

```
规划(身份路由+细纲一致性+参考素材) → 写作(主角主动表达节点) → 举证自检(读者×编辑双通道) → 反AI味润色(成因层诊断+Prompt Defense) → 落库(Change Report+6状态+meta+日志+BM25/FTS索引)
```

每个阶段只读必要的参考文件，产出明确的交付物，阶段间不传递历史报错。

## 分层架构

- **技能层（通用）**：写作方法、模板、工作流 SOP — 写在 Skill 文件里，跨项目复用
- **项目层（每本书）**：story/truth/（状态）+ pools/（素材池）+ 设定/ + 大纲/ + 正文/ — 每个项目独立
- **章节层（动态）**：声线章态、规划清单 — 阶段①输出里，当章用完即弃

## 素材池（pools/）

池子是 **Agent 自动拆解对标书的产物**，不是凭空建的，也不是用户手动填的。空池子没有价值。

| 池子 | 内容 | 用途 |
|------|------|------|
| `author_dna/` | 作者写作习惯（文风定位/句式/节奏/词汇） | 风格校准 |
| `planner/` | 卷结构/伏笔编排/情绪曲线/节奏统计 | 节奏校准 |
| `unit/` | 事件单元（情绪标记+节奏类型+完整事件链） | 同类事件参考 |
| `reference/techniques/` | 8大写作技巧方法论 | 知道"怎么写" |
| `reference/samples/` | 精选段落（按5条标准筛选入池） | 看"别人怎么落地" |
| `knowledge/` | 事实知识（历史/医学/军事等） | 专业场景查证 |

**拆解机制：**
- **谁来拆**：Agent 自动拆，用户只需提供对标书
- **怎么拆**：两阶段——快速预览（前3章+整体结构）→ 用户确认 → 深度拆解（按档位全量）
- **判断标准**：Reference 入池需通过 5 条非AI味标准（≥4条才入池）
- **每本书独立建池**：随项目创建，随项目归档，不跨书复用

**入池原则**：只放对标书拆解的高质量内容，不放自己的稿件（质量上限低于对标书，入池反而拉低水平）。

## 文件体积控制

- SKILL.md ≤ 5KB（路由入口）
- 单状态文件 ≤ 8KB
- 单次强制加载总量 ≤ 12KB
- 池子内容按需加载，不常驻上下文

## 项目历程

### 第一代：novel-writer-jy v5.4（纯 Skill，硬约束路线）

100+ 条硬约束的"规则约束AI"路线。暴露问题：呆板（防守式写作）、只读一半（27KB超注意力范围）、不遵守约束（约束超载）、乒乓球短句（为了规避检测走向另一个极端）。

### 第二代：novel-writer-pure（Python 项目，重型架构路线）

Python + SQLite + 多 Agent 的工程化路线。暴露问题：维护成本失控、架构过重、复杂度超过了它要解决的问题。

### 第三代：story-engine-skill v6.0（纯 Skill，Guide 引导路线）

回归纯 Markdown Skill，Guide 引导而非禁止。暴露问题：丢了关键能力（知识库/Hook/审核）、SKILL.md 还是太大、AI 味问题没解决。

### 第四代：Novel Engine v1.0（融合方案）

综合 v5.4 和 v6.0 的优点。去单元架构、去心智6问、3 条铁律、4 问自检、evidence_ids 强制举证、纯 Markdown。

### 第五代：Novel Engine v1.1（声线与质感）

双层声线系统（基线+章态）、示范驱动替代黑名单、冰山法则、对话不对称三原则。解决句子层面的 AI 味问题。

### 第六代：Novel Engine v1.2（状态体系 + 素材池）

**状态体系 + 素材池** 结构性升级：

1. **story/truth/ 四层状态中心**：characters/world/hooks/relationships 是唯一真相来源，基线摘要+当前状态双层结构，强制加载但体积可控
2. **Change Report 驱动落库**：先出报告再改状态，所有变更可追溯
3. **pools/ 素材池（项目级）**：对标书拆解的高质量内容作为风格和结构锚点，techniques（方法论）+ samples（实战样本）双层
4. **证据引用改为原文片段**：从行号改为 source/excerpt 格式，避免行号偏移导致的证据失效
5. **技能/项目分层**：技能目录只存模板和参考，项目目录存内容，每个项目独立的状态和素材池
6. **入口B迁移路径**：导入已有项目时，从当前章节往前推3章重建状态

### 第七代：Novel Engine v1.3（行为验证 + 质量闭环）

**行为验证 + 对照示范 + 质量闭环** 升级：

1. **对照式转换示范**：4篇示范全部升级为 "原版→AI劣化版→解析表" 三层结构，学转换动作而非模仿词汇
2. **四大转换原则（跨题材通用）**：心理→动作 / 解释→结果 / 对称→不对称 / 总结→落物，覆盖核心写作技巧
3. **行为验证自检**：4问从"自夸式评估"改为"行为模式检测"，先检测有没有问题行为，再引用证据
4. **3轮修正上限 + Best Version 保留机制**：防止越改越差，每轮打综合分，最终输出分数最高的版本
5. **状态优先级系统**：5级裁决（世界规则 > 硬边界 > 核心性格 > 章态 > 剧情需求），解决长期漂移问题
6. **review_status 标记**：full_pass / partial_pass / needs_human_review，给作者明确的审稿优先级

### 第八代：Novel Engine v1.3.1（对标书自动拆解补全）

**对标书拆解体系补全 + 若干加固** 补丁升级（参考 oh-story 拆书方法论）：

1. **Agent 自动拆解**：用户只需提供对标书，Agent 负责读、分析、判断、入池。修正了"用户手动拆"的歧义
2. **两阶段拆解模式**：快速预览（前3章+整体结构+适配度评估）→ 用户确认 → 深度拆解（按档位全量）。避免一上来就全文暴力拆解
3. **拆解判断标准**：Reference 入池 5 条标准（逆向应用 04-anti-ai.md），≥4条才入池。Agent 是"筛选+分析"，不是"复制+粘贴"
4. **Unit 情绪标记**：每个事件单元标注情绪烈度（-9~+9）+ 节奏类型，写特定情绪场景时可快速对标
5. **文风整体定位**：Author DNA 增加一句话文风、冰山程度、非AI味程度、叙事距离等整体定位
6. **节奏量化统计**：Planner 增加信息释放频率、章节内部节奏模式、开篇节奏等量化数据
7. **强制加载刚性约束**：阶段①未输出完整确认清单，禁止进入阶段②。把"必须读"变成硬门槛
8. **每本书独立建池**：pools/ 随项目创建随项目归档，不跨书复用，避免题材间风格污染

### 第九代：Novel Engine v1.3.2（用户级素材库 + 技能导航体系）

**从"项目级素材池"扩展为"用户级 + 项目级"双层体系**，并补全跨文件路由导航：

#### 一、用户级素材库 library/

把创飞 AI 资料包中可长期复用的内容提炼成用户级素材库：

| 目录 | 内容 | 数量 |
|------|------|------|
| `library/techniques/` | 通用写作方法论（剧情收获推演/雪花写作法/爽点设计/人物四维塑模/开篇钩子/反派立体塑造/群像文写作等）| 8 套 |
| `library/genres/` | 题材风格库（辰东式玄幻 + 斩神式都市神话）| 2 个题材包 |
| `library/knowledge/` | 通用知识库索引（古代文史/人设/世界观/民俗玄学/类型文/描写素材/套路工具）| 7 大类精选 |
| `library/platforms/` | 平台适配指南（番茄/起点/晋江/七猫/飞卢/知乎/书旗等）| 9 大平台 |

#### 二、拆解方法论独立成文

把"如何拆书"做成完整的 Agent 执行手册 `templates/pools/拆解方法论.md`，包含：
- 5 个池子各自的拆解目标/方法/输出格式
- 两阶段流程（快速预览 → 深度拆解）
- 拆解质量自检 6 条清单
- 拆解伦理声明

#### 三、文件导航体系

为全部 34+ 个文件统一加上头部导航块，格式：
```
📍 位置 — 在整个体系中处于什么位置
⬆️ 上游 — 从哪里进来、谁调用它
⚠️ 必读前置 — 执行前必须读什么
📚 相关参考 — 互补的、可以一起读的文件
⬇️ 下游 — 用完去哪里、输出给谁
```

关键交叉引用加固：
- `03-self-review.md` 检测到 AI 味时明确指向 `04-anti-ai.md` 的修正方法
- `02-writing-guide.md` 与 `04-anti-ai.md` 的互补关系明示
- 拆书模板都指向 `拆解方法论.md` 作为"拆前必读"
- 强制加载刚性：SKILL.md 阶段①加"未输出确认清单禁止进入②"

#### 效果验证

以《星尘方舟》第1章 v1.3.2 重写为例，3 轮迭代：
- r1：初版写作（5600字），4 问自检 full_pass
- r2：用户发现"乒乓球对话"问题，按原则三重写5 处对话段落
- r3：用户发现"他"连续开头机械感问题，按"动作/物件主语"原则修6 处段落

最终 v1.3.2 = 5750字 / full_pass / 4 问全过 / 4 伏笔全埋。
