# Novel Engine v1.4

工业级网文写作 Skill：纯 Markdown 状态机（主）+ 检索运行时（runtime/，BM25+FTS 已落地，ZVEC 可选增强，唯一 Python 部件）。**技能只存模板，项目存内容。**

## 解决什么问题



| 痛点              | 本引擎方案                                                        |
| --------------- | ------------------------------------------------------------ |
| AI 写作呆板         | 去硬约束，改示范驱动（Few-shot）；反 AI 味从黑名单重构为质感标杆                       |
| Agent 跳读 / 只读一半 | 单文件 ≤8KB，单次强制加载 ≤12KB，文件头加 "后果提示"                            |
| Agent 不遵守约束     | 3 条铁律（底线）+ 其余全部降为 Guide；自检强制 evidence\_ids 证据链               |
| 假自检             | 4 问必须标注原文片段，无证据的 "通过" 判定无效                                   |
| 乒乓球式短句 / 装酷感    | 对话不对称三原则 + 双层声线系统                                            |
| 不敢留白 / 解释腔      | 冰山法则（默认读者看过同类作品，只写物理结果不写原理）                                  |
| 角色 OCC（出戏）      | 基线档案（永久）+ 章态（每章动态），章态必须落在基线情绪光谱内                             |
| 记忆漂移 / 前后矛盾     | 故事/真相/ 6 文件状态中心（+objects/timeline），Change Report 驱动更新  |
| 检索靠全文扫描         | ZVEC 混合检索（dense+BM25 + 防剧透 + 知情权过滤），章节 YAML 迁 故事/元数据 供索引 |
| 身份单一            | 作者 × 编剧 × 编辑 × 读者身份路由，市场调查三档（快速 / 标准 / 深度）                   |
| AI 味复发          | 成因层诊断 7 层 + AI 味指数五档 + Prompt Defense 防诱导                    |
| 长篇失控            | Obsidian 叙事总览（角色 / 世界观 / 伏笔 / 章节地图 / 关系网）+ 每章流程日志            |
| 风格漂移            | 对标书拆解素材池（素材池/），Author DNA 风格锚点 + 高质量样本参考                   |
| 对标书拆解靠人工        | Agent 自动拆解（两阶段：快速预览→深度），带判断标准筛选入池                            |

## 快速使用



1. 将 `novel-engine/` 整个目录安装为技能

2. 对 Agent 说 "开新书" 或 "导入已有项目"，进入阶段⓪初始化

3. （推荐）选 1-3 本对标书，Agent 自动拆解建立项目素材池（两阶段：快速预览→深度拆解）

4. 说 "写第 1 章" 启动五阶段 SOP

5. 新角色首次登场时，Agent 自动按模板建立基线档案

## 五阶段工作流



```
规划(身份路由+细纲一致性+参考素材) → 写作(主角主动表达节点) → 举证自检(读者×编辑双通道) → 反AI味润色(成因层诊断+Prompt Defense) → 落库(Change Report+6状态+meta+日志+BM25/FTS索引)
```

每个阶段只读必要的参考文件，产出明确的交付物，阶段间不传递历史报错。

## 分层架构



* **技能层（通用）**：写作方法、模板、工作流 SOP — 写在 Skill 文件里，跨项目复用

* **项目层（每本书）**：故事/真相/（状态）+ 素材池/（素材池）+ 设定 / + 大纲 / + 正文 / — 每个项目独立

* **章节层（动态）**：声线章态、规划清单 — 阶段①输出里，当章用完即弃

## 素材池（素材池/）

池子是 **Agent 自动拆解对标书的产物**，不是凭空建的，也不是用户手动填的。空池子没有价值。



| 池子                      | 内容                          | 用途         |
| ----------------------- | --------------------------- | ---------- |
| `author_dna/`           | 作者写作习惯（文风定位 / 句式 / 节奏 / 词汇） | 风格校准       |
| `planner/`              | 卷结构 / 伏笔编排 / 情绪曲线 / 节奏统计    | 节奏校准       |
| `unit/`                 | 事件单元（情绪标记 + 节奏类型 + 完整事件链）   | 同类事件参考     |
| `reference/techniques/` | 8 大写作技巧方法论                  | 知道 "怎么写"   |
| `reference/samples/`    | 精选段落（按 5 条标准筛选入池）           | 看 "别人怎么落地" |
| `knowledge/`            | 事实知识（历史 / 医学 / 军事等）         | 专业场景查证     |

**拆解机制：**



* **谁来拆**：Agent 自动拆，用户只需提供对标书

* **怎么拆**：两阶段 —— 快速预览（前 3 章 + 整体结构）→ 用户确认 → 深度拆解（按档位全量）

* **判断标准**：Reference 入池需通过 5 条非 AI 味标准（≥4 条才入池）

* **每本书独立建池**：随项目创建，随项目归档，不跨书复用

**入池原则**：只放对标书拆解的高质量内容，不放自己的稿件（质量上限低于对标书，入池反而拉低水平）。

## 文件体积控制



* SKILL.md 为路由中枢（三铁律+五阶段+初始化核对+流程门禁，当前约 16KB；体积约束适用于状态文件，SKILL 需保持精简，超标时应拆分到 references/）

* 单状态文件 ≤ 8KB

* 单次强制加载总量 ≤ 12KB

* 池子内容按需加载，不常驻上下文
