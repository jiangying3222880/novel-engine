# ne · 小说创作引擎路由

> 本技能只做**意图分发**，不产出正文。判断完立刻转交对应子技能。

## 一、意图路由表

| 用户说 | 转交 |
|---|---|
| "开新书""建项目""开始写新书""导入已有设定" | `ne-setup` |
| "规划第X章""写细纲""这章写什么""章功能分型" | `ne-outline` |
| "写下一章""继续写""开始写正文""外包写作/给我提示词" | `ne-write` |
| "检验这章""去AI味""自检""遮名测试""写得像不像人" | `ne-review` |
| "存盘""落库""续写上次的""跨会话恢复""检索前文" | `ne-memory` |
| "写个短故事""短篇""单篇完结""抖音推文风" | `ne-short` |
| "有什么技法""群像怎么写""拆对标书""找素材" | `ne-library` |
| "跑门禁""校验项目""打包""同步镜像" | `ne-tools` |

**不确定时**：问一句"你现在是想排这一章的结构，还是直接写正文？"再路由。

## 二、写作三铁律（每个子技能共用，进入前必读）

1. **S1 写前必读**：规划前必须读 `故事/真相/` 6 个状态文件 + `novel-config.json` + 上一章细纲/检验报告 + 滚动窗口（N-5~N 章细纲，**仅冲突链+信息释放两节**）。禁止全量加载设定集——会上下文溢出、跳读、声线崩塌。
2. **章节优先**：以"章节"为唯一基本单元。元数据（causal_links / hooks / emotion_arc / change_summary）统一记入 `故事/元数据/chapter_XXXX.md`，正文文件保持干净无 YAML。进度唯一真相源 = `故事/元数据/index.md`。
3. **S2 物理隔离**：执笔态**只读细纲产物文件**，不读状态文件/规则文本/技法库（multi 物理隔离，single 用三条硬指令模拟）。检验报告必须带 `evidence_ids`，无证据的判定无效。

## 三、初始化核对（继续/重写/完成整本时必做）

项目已有 `novel-config.json` 且指令是"继续写/完成整本/重写"时，**先核对参数再进流程**：

| 核对项 | 缺失/异常时 |
|---|---|
| 要求字数 `target_word_count` | 与预期不符或未定义 → **先向用户确认**，禁止用默认值静默开写；给区间则取中点；验收按 target±15% |
| 正文命名规范 | 未按 `第000X章 <标题>.md` → 先重命名历史正文 |
| 视角/基调/卖点/身份 | 缺失但创作需要 → 提问确认（可后补） |
| 现有正文/状态文件 | 用户说"从头重写" → 先确认是否作废再进 |

> **刚性约束**：参数未核对前禁止产出正文。这一条是"直接开写导致产出不合规范"的根因修复。

## 四、流程门禁（机器强制，Agent 不能自证）

关键动作完成后**必须**跑脚本，PASS 才继续，FAIL 必须修后重跑（退出码 1 = 禁止继续）：

```
python <技能根>/ne-tools/runtime/verify.py --root <项目根> --scope <阶段>
```

| 时机 | scope | 覆盖 |
|---|---|---|
| 项目初始化完成 | `init` | 目录结构 / 真相防污染 / config 合法性 |
| 叙事总览生成后 | `narrative` | 总览骨架 / 双链可解析 / 4 位章号 |
| **每章落库（必跑）** | `settle` | 落库一致 / timeline / hooks / 证据链 / 正文质量 |
| 连续批跑·每 5 章 | `trend` | 退化趋势（逗号/口癖逐章放大） |
| 交付前兜底 | （不写 scope） | 全部 |

> verify.py 是**校验器**（证明结果对），不是执行器。展示层产物仍由 Agent 生成，但生成后必须过门禁。

## 五、子技能清单

| 子技能 | 职责 |
|---|---|
| `ne-setup` | 立项、真相文件初始化、身份配置、模块开关 |
| `ne-outline` | 细纲/骨架、叙事内核、章功能分型、任务字数 |
| `ne-write` | **正文主流程 S1-S4**、执行模式、身份切换、外包分支 |
| `ne-review` | 检验、去 AI 味、遮名测试、evidence 证据链 |
| `ne-memory` | 落库、跨会话续写、滚动窗口、检索、叙事总览 |
| `ne-short` | 短篇全流程（憋压三段式，短篇也走细纲门） |
| `ne-library` | 素材库：技法 / 题材 / 身份档案 / 平台 / 拆书 |
| `ne-tools` | 运行时：门禁脚本、索引、打包、镜像同步 |

**身份（Voice）与环节（Lane）是两个正交的轴**：Lane 决定做什么（S1-S4），Voice 决定以谁的嘴做（作者/编剧/编辑/读者/档案员）。一个 Lane 一个主 Voice。

定稿口径（v2.1）：**作者既执笔又拍板**——情节编剧定，文字由作者在**执笔态**出，拍板由作者在**决策态**做。
> v2.1 删除了原「讲述者」身份：身份矩阵（作者+平台+题材+篇幅）已经定义了"你是谁"，
> 再挂一层独立讲述者是重复的一层，且"作者不执笔"会让执笔角色无人格可加载。
> 声线职责已并入作者档案 §五-§七。**代价**：原来是两个人隔开"写什么/怎么写"，
> 现在靠同一人的**两个状态**隔开——判据是手里的文件（只剩细纲输入包 = 执笔态）。

身份档案在 `ne-library/library/identities/`（作者/编剧/编辑/读者/档案员 5 份），路由规则见 `../ne-write/references/identity-routing.md` §1.1。

## 六、降级：宿主不支持子技能路由时

豆包、网页版 AI 等没有子技能路由能力。此时**不要等宿主分发**，直接按意图读对应子技能的 `SKILL.md`（如写正文读 `../ne-write/SKILL.md`）并内联展开其核心指令。硬门禁（verify.py）在无 Python 环境下跳过，并在流程日志显式标注 `execution_mode=no_python，verify.py 跳过，手动校验：…`——**不静默假装通过**。

## 七、升级 SOP（改完技能必做）

```
python ne-tools/runtime/doc_sync.py update   # 刷新自动索引
git commit                                    # pre-commit 强制跑 doc_sync check
python ne-tools/runtime/deploy.py --apply     # 同步运行镜像
```
