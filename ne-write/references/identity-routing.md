# 身份路由（写作视角 × 流水线环节 → 专业身份）

## 1. 两个轴，不要混为一谈

> **这是全文最容易搞错的一件事**：技能里有两套"角色"，它们不是一个维度。

| 轴 | 叫什么 | 回答什么问题 | 取值 | 定义处 |
|----|--------|-------------|------|--------|
| **轴一 · 环节（Lane）** | S1-S4 | 这一步**做什么**（结构契约：输入输出是什么） | S1 骨架 / S2 血肉 / S3 检验 / S4 落库 | `workflow-detail.md`、`execution-modes.md` |
| **轴二 · 视角（Voice）** | 身份 | 这一步**以谁的嘴和眼睛**做 | 作者 / 编剧 / 编辑 / 读者 / 档案员 | 本文件 + `library/identities/` |

- **Lane 决定产物文件名和门禁**（可被 verify.py 校验）。
- **Voice 决定措辞、取舍偏好、隔离边界**（不可被机器校验，靠身份档案 + 强制问答）。
- 同一个 Voice 可在多个 Lane 出现（作者贯穿立项、S2、S4）；同一个 Lane 只有一个主 Voice。

### 1.1 作者的两个状态（v2.1 · 删除讲述者后的核心防护）

**作者既执笔又拍板**，这是 v2.1 相对 v2.0 最大的变化。原来这两件事分给作者和讲述者两个人，
现在合并到一个人身上，靠**状态**而不是**身份**隔开：

| | 决策态 | 执笔态 |
|---|---|---|
| 出现环节 | 立项 / S4 裁决 / 打回裁决 | **S2 血肉** |
| 能看到什么 | 全部 | **仅 S2 输入包**（细纲 + 声音样本 + 上章结尾） |
| 能否改情节 | 能 | **不能** |
| 判据 | 握着状态文件/技法库 | 手里只剩细纲输入包 |

> **两者不许同时握着。** 越界症状：正文里冒出"这一笔是为了""前面埋下"等规划语言 = 框架显形。
> 详见 `../../ne-library/library/identities/作者.md` §六。

### 1.2 五个身份的状态细分（v2.1 · 一身份两态，判据各不相同）

> **为什么每个身份都要分态**：一个身份在不同环节干的事不一样，混在一张卡上会导致
> "用上一环节的习惯做下一环节的事"（编剧把单章细纲写成卷纲、读者第一遍就给解法）。
> 每个身份的两个态都有**各自的判据**，判据越物理越好——靠自觉守不住。

| 身份 | 状态 A | 状态 B | **判据（一句话）** | 越界症状 |
|------|--------|--------|-------------------|---------|
| 作者 | 决策态（立项/S4 裁决） | **执笔态**（S2） | **手里的文件**：握着状态文件=决策态，只剩细纲输入包=执笔态 | 正文冒出规划语言 |
| 编剧 | **架构态**（卷纲/暗线/体检） | **排布态**（S1 单章） | **章节地图 vs 单章任务** | 细纲写成缩微卷纲 / 替执笔态写台词 |
| 编辑 | **预判态**（立项/S1 前） | **审阅态**（S3） | **能不能引用正文**：引不到=预判态 | 无正文就下"这本能火" / 动笔改稿 |
| 读者 | **首读态**（第一遍） | **定位态**（第二遍） | **读过几遍**：第一遍只许报感受 | 第一遍就给解法 / 用理论解释感受 |
| 档案员 | **写入态**（S4） | **检索态**（S1 前/恢复/检索） | **会不会改动 `故事/` 下的文件** | 半途提交 / 检索时顺手改状态 |

**共通铁律**：两态不许同时握着，切换时按身份档案里的判据自问一次。
状态细分是给**同一个 Agent** 用的认知开关；multi 模式下作者执笔态仍应真的物理隔离（见 `./execution-modes.md` §2.2）。

## 2. 默认内置身份（5 个）

| 身份 | 视角 | 主战场环节 | 核心产出 |
|------|------|-----------|---------|
| **作者** | 卖点·边界·裁决 **+ 声音·视角·语体** | 立项 / **S2 血肉（执笔态）** / S4 裁决 | 卖点、基调、边界、**正文**、包装类产出（简介/导语/投稿文，见 `../../ne-library/library/packaging.md`） |
| 编剧 | 情节·冲突·节奏·悬念 | **S1 骨架** | 每章有戏、冲突升级、钩子管理、四维细纲 |
| 编辑 | 读者体验+商业留存 | **S3 检验**（留存通道） | 开篇留存、连载风险、卖点落地 |
| 读者 | 第一遍直觉·代入 | **S3 检验**（体验通道） | 弃书点、体验反馈（不给解法） |
| 档案员 | 数据一致性 | **S4 落库**（写入态）/ 检索·恢复（检索态） | 原子提交、truth 写入、状态推进、索引重建 |

> **定稿口径（v2.1）**：情节由编剧定，**文字由作者在执笔态出**，拍板由作者在决策态做。
> 手里的文件决定你在哪个状态——这是唯一的判据。

**身份档案（5 份齐全）**：`../../ne-library/library/identities/作者.md` · `编剧.md` · `编辑.md` ·
`读者.md` · `档案员.md`。每份均含 §状态细分 与 §与其他身份的边界。

> ~~档案员无身份档案~~ **已于 v2.1 补齐**（此前 5 个 Voice 只有 4 份档案）。

## 3. 环节 × 身份 路由表（S1-S4 对齐版）

| 环节 | 主身份 | 辅助身份 | 该身份查什么 |
|------|--------|---------|-------------|
| 立项（S0） | **作者**（决策态） | 编辑 | 卖点/读者/差异点/边界（作者档案）；开篇留存预判（编辑档案） |
| **S1 骨架** | **编剧** | 作者（决策态） | 本章有戏/冲突升级/钩子计划（编剧档案）；长线卖点对齐（作者档案） |
| **S2 血肉** | **作者（执笔态）** | — | 声音是否符合样本；是否夹带规划语言；是否越过细纲边界 |
| **S3 检验** | **读者 → 编辑**（顺序不可颠倒） | — | 体验通道先走（读者：Q1/Q4 直觉）；留存通道后走（编辑：主角五项/前100字/连载风险） |
| 打回重写 | 作者（执笔态） | 编辑（给方向不给笔） | 表达问题回 S2；**骨架问题才回 S1**（A-04 分层） |
| **S4 落库** | **档案员** | **作者**（决策态·变更裁决） | 状态变更原子提交（档案员）；真相变更最终拍板（作者档案 §三） |

**为什么没有"润色"环节**：`workflow-detail.md:195` 已定——检验只出报告不改正文，
表达问题回 S2 由执笔态重写，不再设独立润色阶段。

## 4. 身份可读文件边界

> 身份的"信息访问边界"决定这个视角真实与否。身份能接触的文件范围要显式声明；
> 尤其**读者/编辑"只知道该知道的"，才能产生真正独立的质疑**。

| 身份 | 默认可读（视角所需） | 默认不可读（防作弊/防越权） |
|------|--------------------|---------------------------|
| 作者（决策态） | 正文、细纲、世界观、真相、facts、身份档案、元数据 | 无 |
| **作者（执笔态）** | **仅 S2 输入包**：细纲_第XXXX章.md（四维）+ 声音样本 + 上章结尾 | 技法库、六状态文件、真相原文、角色卡原文、任何检验规则 |
| 编剧 | 细纲、章节地图、真相、objects、hooks、chapter元数据 | 旁白润色层、最终正文深审 |
| 读者 | **仅正文**（+当前章句尾） | 细纲、真相、hooks、facts、伏笔表、objects |
| 编辑 | 正文、元数据（chapter_XXXX.md）、章节地图、hooks、落点 | 细纲作者动机、真相深层、facts 内部 |
| 档案员（写入态） | 全部（唯一写窗口，见 execution-modes.md §2.3） | 无 |
| 档案员（检索态） | 全部（**只读**） | **不许写盘**——检索时发现不对，改为提报告，不顺手改 |

- **执笔态"只读输入包"是 S2 隔离核心**：看不到技法库和状态文件，所以不可能一边写一边套技法、偷看伏笔表。
  代价是**声音也会顺便被隔离掉**——解法不是放松隔离，而是把声音**编译进**输入包（细纲 §5 声线 + 作者档案 §5.2 样本）。
  **别用"让执笔态多读点"来破隔离。**
- **读者"仅读正文"是 S3 隔离核心**：真正的读者不知道作者意图，只看到文本。带着"作者背景知识"读，等于评论家作弊。
- **定位说明**：single 模式下这是"语义/纪律约束"，不是技术门禁——同一会话技术上能读所有文件，靠强制问答自锚。
  multi 模式下执笔态应为**真的物理隔离**（独立子 Agent，见 `./execution-modes.md` §2.2），两者都不能省。

## 5. 身份档案分层（技能级基线 + 项目级覆盖）

- **技能级内置**：`library/identities/`（**作者 / 编剧 / 编辑 / 读者 / 档案员 5 档案**，通用基线；每份含状态细分与边界表）
- **项目级覆盖**：项目根 `配置/身份/*.md` 覆盖技能级对应字段（每本书可定制卖点/读者/边界/阈值/**声音**）
- **加载规则**：项目级存在则读项目级，否则读技能级；两级不合并存储，避免漂移。
- **唯一例外：作者档案的 §5.2 声音样本必须项目级覆盖**。技能级只留槽位、给不出你的声音；
  不覆盖 = 通用书面语兜底 = 十本书一个味。这是设计上的必然，不是配置漏填。
  **这是当前治 AI 味的最大缺口——需要作者本人提供 200-400 字成稿。**

## 6. 平台 × 题材 维度

- **平台**：`library/platforms/`（8 张风格卡，匹配的是**风格口味**不是审核规约）。
  立项 Step 4.5 由世界观+大纲自动反推，见 `../../ne-setup/references/题材与平台自动确认.md`。

- **受众**：项目级 `配置/身份/作者.md` 的 target_reader 字段。

## 7. 身份切换纪律

1. **一个环节一个主身份**，不混用。S3 检验必须**读者先读、编辑再审**（体验在前，留存在后）。
2. **编辑/读者意见是建议**，作者在决策态最终裁决（作者档案 §三 保留判断权）。
3. **执笔态不参与决策**：不改情节、不评判卖点、不决定留不留。发现结构问题 → 停笔回 S1，不许自行修正。
4. **身份档案不推翻世界观硬规则**：任何身份的建议都受 故事/真相 世界规则约束。
5. 缺失项目级覆盖时**自动回退技能级基线**，不中断流程（声音样本除外，见 §5 例外）。

## 7.2 硬冷切换（强制认知切换）

> 同一个 Agent 执行所有身份时，风险是"自卖自夸"——它很难真忘掉自己写过什么。
> 用**强制前置问答**把这些切换点掰开。

**硬切换点 0：S1 → S2（进入执笔态之前）**
1. 我手里只有**细纲输入包 + 声音样本**吗？（技法库/状态文件是否已收走）
2. 我读过本项目**声音样本段**了吗？（没读就不许动第一个字）
3. 我现在允许改情节吗？（**不许**。发现结构问题 → 停笔回 S1）
4. 我接下来写出的第一句，听起来像样本里的嘴，还是像说明书？

**硬切换点 A：S2 → S3 读者自检**（进入"读者先读"之前）
在 S3 读到正文前，先停止、回答下面 4 问，再读正文：

1. 你手里现在**只有本章正文**吗？（若还在握细纲/真相/伏笔表 → 先收走）
2. 你读的是什么类型的书？（**只从本章正文**判断，不引用细纲）
3. 本章开篇后，你的**第一直觉感受**是什么？（不引用任何作者意图）
4. 你读到哪里**开始想往下翻**？哪里**想跳**？（读者只报体验，不给解法）

**硬切换点 B：读者 → 编辑审阅**（进入"编辑再审"之前）
读完正文后、开始审阅前，回答：

1. 你的判断基于**正文 + 元数据**，有没有误把"读者感觉"当"留存依据"？
2. 主角五项 / 前100字 / 连载风险里，哪些是**文本证据支持**、哪些只是"我写的所以我觉得好"？
3. 你给出的修改是**方案**（编辑只管"改不改、怎么改方向"），不是直接动笔（动笔重写交 S2 执笔态）。

> 冷切换解决的是"认知惯性"，不是"技术隔离"：读者/编辑技术上仍能读全量文件，靠这几问把自己拽进独立视角。
