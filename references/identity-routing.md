# 身份路由（写作视角 × 流水线环节 → 专业身份）

## 1. 两个轴，不要混为一谈

> **这是全文最容易搞错的一件事**：技能里有两套"角色"，它们不是一个维度。

| 轴 | 叫什么 | 回答什么问题 | 取值 | 定义处 |
|----|--------|-------------|------|--------|
| **轴一 · 环节（Lane）** | S1-S4 | 这一步**做什么**（结构契约：输入输出是什么） | S1 骨架 / S2 血肉 / S3 检验 / S4 落库 | `workflow-detail.md`、`execution-modes.md` |
| **轴二 · 视角（Voice）** | 身份 | 这一步**以谁的嘴和眼睛**做 | 作者 / 编剧 / **讲述者** / 编辑 / 读者 / 档案员 | 本文件 + `library/identities/` |

- **Lane 决定产物文件名和门禁**（可被 verify.py 校验）。
- **Voice 决定措辞、取舍偏好、隔离边界**（不可被机器校验，靠 ARCHIVECTION-by-hand 档 + 强制问答）。
- 同一个 Voice 可在多个 Lane 出现（作者贯穿立项与 S4）；同一个 Lane 只有一个主 Voice（S2 只能是讲述者）。

**v1.9.1.3 补錄**：`讲述者` 此前在全技能出现 54 次却**没有对应身份档案**（library/identities/ 下缺 讲述者.md），
导致 S2 执笔角色无人格可加载——这正是 D-11「物理隔离把文体声音也挡掉了」的结构性成因之一。已补。

## 2. 默认内置身份（5 个 · 新增讲述者）

| 身份 | 视角 | 主战场环节 | 核心产出 |
|------|------|-----------|---------|
| 作者 | 全局·卖点·边界·裁决 | 立项 / S4 落库裁决 | 卖点、基调、边界、包装类产出（简介/导语/投稿文，见 library/packaging.md） |
| 编剧 | 情节·冲突·节奏·悬念 | **S1 骨架** | 每章有戏、冲突升级、钩子管理、四维细纲 |
| **讲述者** | 声音·视角·距离·语体 | **S2 血肉**（唯一产出正文的身份） | 正文。动笔之外一律不管 |
| 编辑 | 读者体验+商业留存 | **S3 检验**（留存通道） | 开篇留存、连载风险、卖点落地 |
| 读者 | 第一遍直觉·代入 | **S3 检验**（体验通道） | 弃书点、体验反馈（不给解法） |
| 档案员 | 数据一致性 | **S4 落库** | 原子提交、truth 写入、状态推进 |

> 作者 **不执笔**。历史上"②写作 = 作者"是旧六段流程的口径，与 S1-S4 的"讲述者"冲突；
> 现统一定稿：**情节由编剧定，文字由讲述者出，拍板由作者做。**

## 3. 环节 × 身份 路由表（S1-S4 对齐版）

| 环节 | 主身份 | 辅助身份 | 该身份查什么 |
|------|--------|---------|-------------|
| 立项（S0） | **作者** | 编辑 | 卖点/读者/差异点/边界（作者档案）；开篇留存预判（编辑档案） |
| **S1 骨架** | **编剧** | 作者 | 本章有戏/冲突升级/钩子计划（编剧档案）；长线卖点对齐（作者档案） |
| **S2 血肉** | **讲述者** | — | 声音是否符合 §五 样本；是否夹带规划语言；是否越过细纲边界 |
| **S3 检验** | **读者 → 编辑**（顺序不可颠倒） | — | 体验通道先走（读者：Q1/Q4 直觉）；留存通道后走（编辑：主角五项/前100字/连载风险） |
| 打回重写 | 讲述者 | 编辑（给方向不给笔） | 表达问题回 S2；**骨架问题才回 S1**（A-04 分层） |
| **S4 落库** | **档案员** | **作者**（变更裁决） | 状态变更原子提交（档案员）；真相变更最终拍板（作者档案 §3） |

**为什么没有"润色"环节**：`workflow-detail.md:195` 已定——检验只出报告不改正文，表达问题回 S2 由讲述者重写，
不再设独立润色阶段。旧编号体系里的「④润色」作废，对应的两层审理（00 诊断 / 04 出戏检查）并入 S3 检验报告。

## 4. 身份可读文件边界

> 身份的"信息访问边界"决定这个视角真实与否。身份能接触的文件范围要显式声明；尤其**读者/编辑"只知道该知道的"，才能产生真正独立的质疑**。

| 身份 | 默认可读（视角所需） | 默认不可读（防作弊/防越权） |
|------|--------------------|---------------------------|
| 作者 | 正文、细纲、世界观、真相、facts、身份档案、元数据 | 无（作者是全局） |
| 编剧 | 细纲、章节地图、真相、objects、hooks、chapter元数据 | 旁白润色层、最终正文深审 |
| **讲述者** | **仅 S2 输入包**：细纲_第XXXX章.md（四维）+ 声音样本区 §五 + 上章结尾 | 技法库、六状态文件、真相原文、角色卡原文、任何检验规则 |
| 读者 | **仅正文**（+当前章句尾） | 细纲、真相、hooks、facts、伏笔表、objects |
| 编辑 | 正文、元数据（chapter_XXXX.md）、章节地图、hooks、落点 | 细纲作者动机、真相深层、facts 内部 |
| 档案员 | 全部（唯一写窗口，见 execution-modes.md §2.3） | 无 |

- **讲述者"只读输入包"是 S2 隔离核心**：它看不到技法库和状态文件，所以不可能一边写一边套技法、一边偷看伏笔表。
  代价是**声音也会顺便被隔离掉**——解法不是放松隔离，而是把声音**编译进**输入包（细纲 §5 声线 + 讲述者档案 §五 样本）。
  这是 D-11 / v1.9.2「声音包」要解决的题，别用"让讲述者多读点"来破隔离。
- **读者"仅读正文"是 S3 隔离核心**：真正的读者不知道作者意图，只看到文本。带着"作者背景知识"读，等于评论家作弊，读者身份就废了。
- **定位说明**：在 single 模式下这是"语义/纪律约束"，不是技术门禁——同一会话技术上能读所有文件，靠的是强制问答自锚。
  在 **multi 模式下讲述者是真物理隔离**（独立子 Agent，见 execution-modes.md §2.2），两者都不能省。

## 5. 身份档案分层（技能级基线 + 项目级覆盖）

- **技能级内置**：`library/identities/`（**作者 / 编剧 / 讲述者 / 编辑 / 读者 5 档案**，通用基线）
- **项目级覆盖**：项目根 `配置/身份/*.md` 覆盖技能级对应字段（每本书可定制卖点/读者/边界/阈值/**声音**）
- **加载规则**：项目级存在则读项目级，否则读技能级；两级不合并存储，避免漂移。
- **唯一例外：讲述者档案必须项目级覆盖**。技能级只留槽位、给不出你的声音；
  不覆盖 = 讲述者用通用书面语兜底 = 十本书一个味。这是设计上的必然，不是配置漏填。

## 6. 平台 × 题材 维度

- **平台**：`library/platforms/`（起点/番茄/晋江/飞卢…平台风格），立项阶段确定目标平台。
- **题材**：`library/genres/`（题材风格包），立项阶段按题材选 1-2 个。
- **受众**：项目级 `配置/身份/作者.md` 的 target_reader 字段。

## 7. 身份切换纪律

1. **一个环节一个主身份**，不混用。S3 检验必须**读者先读、编辑再审**（体验在前，留存在后）。
2. **编辑/读者意见是建议**，作者身份最终裁决（作者档案 §3 保留判断权）。
3. **讲述者不参与决策**：它不改情节、不评判卖点、不决定留不留。发现结构问题 → 停笔回 S1，不许自行修正。
4. **身份档案不推翻世界观硬规则**：任何身份的建议都受 故事/真相 世界规则约束。
5. 缺失项目级覆盖时**自动回退技能级基线**，不中断流程（讲述者除外，见 §5 例外）。

## 7.2 硬冷切换（强制认知切换）

> 同一个 Agent 执行所有身份时，风险是"自卖自夸"——它很难真忘掉自己写过什么。用**强制前置问答**把这些切换点掰开。
> 原本只设 2 个切换点；v1.9.1.3 起**新增硬切换点 0（进讲述者）**——因为前两个点都在 S3，谁也没管"S2 动笔前把自己掰成讲述者"这件事。

**硬切换点 0：S1 → S2（进入讲述者执笔之前）** ← 新增，直接对应 D-11
1. 我手里只有**细纲输入包 + 声音样本**吗？（技法库/状态文件是否已收走）
2. 我读过本项目**声音样本段**了吗？（没读就不许动第一个字）
3. 我现在允许改情节吗？（**不许**。发现结构问题 → 停笔回 S1）
4. 我接下来写出的第一句，听起来像 §五 样本里的嘴，还是像说明书？

**硬切换点 A：S2 → S3 读者自检**（进入"读者先读"之前）
在 S3 读到正文前，先停止、回答下面 4 问，再读正文：

1. 你手里现在**只有本章正文**吗？（若还在握细纲/真相/伏笔表 → 先收走）
2. 你读的是什么类型的书？（**只从本章正文**判断，不引用细纲）
3. 本章开篇后，你的**第一直觉感受**是什么？（不引用任何作者意图）
4. 你读到哪里**开始想往下翻**？哪里**想跳**？（读者只报体验，不给解法）

**硬切换点 B：读者 → 编辑审阅**（进入"编辑再审"之前）
读完正文后、开始审阅前，回答：

1. 你的判断基于**正文 + 元数据**，有没有误把"读者感觉"当"留存依据"？
2. 主角五项 / 前100字 / 连载风险里，哪些是**文本证据支持**、哪些只是"我写的所以我觉得好"？
3. 你给出的修改是**方案**（编辑只管"改不改、怎么改方向"），不是直接动笔（动笔重写交 S2 讲述者，表达问题由 S3 判定后打回）。

> 冷切换解决的是"认知惯性"，不是"技术隔离"：读者/编辑同时技术上仍能读全量文件，靠这 4/3 问把自己拽进独立视角。
