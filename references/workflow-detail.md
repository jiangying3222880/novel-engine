# S1-S4 物理隔离流水线详解（v1.9）

## 流程总览

```
用户："写第X章"
    │
    ▼
[S1 骨架·编剧] 读取 分卷大纲/章节大纲 + 上章结尾 + active hooks + 角色状态 + 声线卡
    │           滚动窗口：读 N-5~N 章细纲（仅冲突链+信息释放两节）
    │           从 library/techniques/ 路由骨架模板
    │           产出：细纲_第XXXX章.md（四维骨架，落盘）
    │
    ▼
[细纲门·检验] 硬性结构检查（verify 可校验）+ 软性删节推理（写"删这节下一节缺什么"）
    │           不通过 → 节级打回 S1（≤2 轮）
    │
    ▼
[S2 血肉·讲述者] 输入包 = 仅细纲_第XXXX章.md + config 字数（物理最小）
    │           多窗口：独立子 Agent，物理看不到规则/状态/技法库
    │           单窗口（降级）：三条硬指令模拟隔离 + 降级声明记录
    │           产出：正文/第000X章 <标题>.md（干净正文，无 YAML）
    │
    ▼
[正文门·检验] 骨架逐节点对齐 + 双视角评估（读者+编辑）+ 遮名测试
    │           骨架问题 → 节级回 S1；表达问题 → 回 S2（≤2 轮，保 Best）
    │
    ▼
[S3 检验·编辑] 产出：检验报告_第XXXX章.md（双视角，落盘）
    │
    ▼
[S4 落库·档案员] 暂存 → 校验 → 提交 → 回滚（原子）
    │           产出：Change Report + 6 状态更新 + 日志 + 输入包存档
    │
    ▼
完成，等待用户下一指令
```

## 阶段间交互规范

- 每个阶段完成后，向用户输出该阶段的产出物（产物文件路径）
- 用户可以喊停修改，修改后从当前阶段继续
- 不要把多个阶段的结果合在一起一次性输出（防止跳过门禁）
- 如果用户说"直接写不要规划"，这是**用户主动豁免规划**（Agent 不得自行豁免）：仍需口述确认本章**内核三联**（目标/阻力/后果，一句话即可，缺一项必须补齐），且 S1 细纲最小版（冲突链四节点 + 任务字数）仍必须产出。豁免只跳过"完整四维细纲"，不跳过"想清楚这一章要干什么"。

## S1 骨架（编剧 · 规划）

### 输入

```
强制读取：
  大纲/分卷大纲.md + 大纲/章节大纲.md — 本章在卷内的定位
  故事/元数据/上一章（细纲 + 检验报告）— 上章结尾状态
  故事/真相/hooks.md — active 伏笔（只读当前需要推进/回收的）
  故事/真相/characters.md — 角色卡（提取声线 + 知识边界，压缩进细纲）
  novel-config.json — 目标字数 + 正文目录
滚动窗口（只读 N-5~N 历史细纲，仅冲突链+信息释放两节）：
  大纲/细纲_第XXXX章.md（前 5 章）— 跨章连续性
```

```
按需读取：
  library/techniques/ — 骨架模板路由（憋压三段式/冲突链+信息差/身份逆转/三线并行）
  素材池/author_dna/ — 风格校准
  素材池/planner/ — 节奏校准
  设定/角色声线.md — 新角色或声线存疑时
```

### 产出：细纲_第XXXX章.md（按 templates/细纲模板.md，四维骨架）

- 冲突链（叙述形态四节点：想要/阻拦/弄砸/代价）
- 情绪弧（憋压层次/临界点/爆发点）
- 信息释放（新信息/藏的/钩子点）
- 声线要求（从角色卡透传，标注来源）
- 角色状态最小摘要（每角色一行"知道什么/不知道什么"）
- 任务字数（每节目标，合计落 config ±15%）
- 伏笔计划（埋/推/收）

### 编剧职责边界（防越界）

- 编剧只管"设计事件和动机"，**不写正文、不写具体文句**
- 细纲必须叙述形态（"林野发现老赵声音可疑→备份语音→设局"），禁止流程图形态
- 声线不是自由发挥，是从 characters.md 提取压缩（A-11 + 声线透传）

## 细纲门（S1 → S2 前置 · 检验 Agent 兼任）

### 硬性结构检查（verify.py 可校验）

| 检查项 | 判定 |
|--------|------|
| 每节有任务字数（数字非空） | FAIL → 节级打回 |
| 冲突链四节点有内容 | FAIL → 节级打回 |
| 声线要求覆盖出场角色+标注来源 | FAIL → 节级打回 |
| 角色状态最小摘要存在 | FAIL → 节级打回 |

### 软性删节推理（检验 Agent 做 · 必须写推理过程）

逐节回答："**如果删掉这一节，下一节会缺什么？**"
- 缺 = 链条断 = 力度够
- 不缺 = 注水骨架 = 打回

**节级打回**：只打回有问题的节，打回指令 = "细纲_第XXXX章.md 第 N 节：删节推理不成立（原因一句话）"，编剧只改该节。≤2 轮。

## S2 血肉（讲述者 · 写作）

### 输入包（物理最小 · multi 模式）

```
唯一强制输入：
  故事/元数据/细纲_第XXXX章.md
  novel-config.json（仅 target_word_count + body_dir）
```

**禁止读取**：6 状态文件、writing-guide.md、anti-ai.md、self-review.md、技法库全文、素材池全文。
声线信息已在细纲 §5（透传自角色卡），知识边界已在细纲 §6（角色状态最小摘要），讲述者不需要原始文件。

### multi 模式（物理隔离）

- 独立子 Agent 窗口启动，只加载输入包
- 物理上看不到规则文本/状态文件/技法库 → **不存在"声明隔离"，是结构隔离**
- 产出：干净正文初稿（无 YAML；元数据写 故事/元数据/chapter_XXXX.md）

### single 模式（模拟隔离 · 降级专用）

> ⚠️ single 模式**物理隔离不成立**——同一窗口内 Agent 仍带着之前对话历史。三条硬指令是 single 专用降级方案，**不是隔离的替代品**。

1. **角色重锚定**：动笔前先声明"以下正文仅由讲述者身份产出；因果循环/内核三联/断章规则/模块调度视为已完成背景，本窗口内不调用、不检查、不提及"。
2. **输入最小化**：只呈现细纲_第XXXX章.md 内容 + 目标字数进写作；细纲全文已在盘上，不复制状态/规则/技法文本进写作上下文。
3. **禁读清单**：不 Read anti-ai.md / self-review.md / short-story.md / module-registry.md 全文。

**降级声明记录（D-214 修正措辞）**：single 模式下，落盘证明只证明"Agent 声明了输入是细纲"，**证明不了物理上只看到细纲**。`故事/日志/第XXXX章.md` 记录一行：
```
execution_mode=single，隔离=声明级最小化（三条硬指令），非物理隔离；产物与门禁不减。
```

写作时不解释"我在用什么技巧"，直接输出正文。叙事完整 > 框架展示。

## 正文门（S2 → S3 前置 · 检验 Agent）

| 检查 | 内容 |
|------|------|
| 骨架逐节点对齐 | 细纲每节 → 正文证据（excerpt），✅/❌ |
| 情绪弧核对 | 憋压层次是否到位 |
| 信息释放核对 | 钩子点位置 |

**打回区分**：
- 骨架问题（链条断/没力度/漏节点）→ **节级回 S1**（编剧重设计该节）
- 表达问题（写得太差/声线崩/AI 味）→ **回 S2**（讲述者重写）
- ≤2 轮，保留 Best Version

## S3 检验（编辑 · 只出报告不改稿）

### 输入

```
故事/元数据/细纲_第XXXX章.md（核对基准）
正文/第000X章 <标题>.md（被检对象）
```

### 产出：检验报告_第XXXX章.md（按 templates/检验报告模板.md）

```
├─ 细纲门核对（硬结构 + 删节推理）
├─ 正文门核对（骨架逐节点对齐 + 证据）
├─ 【读者视角】吸引力/憋压感/好奇心
├─ 【编辑视角】节奏/钩子密度/断章位置/爽点
├─ 遮名测试（声线进嘴）
└─ 结论 + 打回方向（骨架→S1 节级 / 表达→S2）
```

### 检验职责边界

- 检验只出报告，**不改正文**（润色并入打回分支：表达问题 → 回 S2 重写，不再独立润色阶段）
- 每个判断必须带 evidence_ids（C-006），无证据的判断无效
- 打回指令只带"文件名 + 原因一句"，**不携带规则/修改建议文本**（防规则回写，A-14）

## S4 落库（档案员 · 原子提交）

### 输入

```
故事/元数据/检验报告_第XXXX章.md（通过判定）
正文/第000X章 <标题>.md（最终版本）
```

### 原子四步（A-07）

1. **暂存**：生成 Change Report（角色/伏笔/时间线/世界规则/关系变化）+ 待落库变更请求 → 暂存区 `故事/日志/暂存_第XXXX章.md`
2. **校验**：verify.py --scope settle 检查 6 状态更新与 Change Report 一致
3. **提交**：通过 → 批量更新 6 状态文件 + 元数据/index + 正文落位
4. **回滚**：失败 → 保留旧状态，不部分更新

### 落库内容

1. 生成本章 Change Report
2. 更新 故事/真相/ 下 6 个状态文件（含 objects/timeline）
3. 更新 故事/元数据/chapter_XXXX.md（change_summary）+ index.md（进度）
4. 写 故事/日志/第XXXX章.md 流程日志（S1-S4 合一）
5. 联动更新 叙事总览/（功能五）+ 重建检索索引（功能八）：
   - BM25+FTS（默认启用，零依赖，必跑）：`python runtime/bm25_fts.py build --root <项目根>`
   - ZVEC（可选增强，仅装了 zvec SDK 时跑）：`python runtime/index.py build --root <项目根>`
6. 新出场/升级角色检查（D 回填）
7. **输入包存档（D-214）**：日志附"本章输入包 = 细纲_第XXXX章.md + 检验报告_第XXXX章.md"（multi=隔离证据链 / single=降级声明记录）
8. **工具痕迹检查（F-09）**：正文开头/结尾无"按照您的要求""继续写"类工具残留

## 滚动窗口（B-02 · 防长篇遗忘）

- **定义：N-5~N（只读历史细纲）**，不含未来章节（N+1~N+5 尚不存在）
- **最小化读取**：历史细纲只读"冲突链 + 信息释放"两节，不读全文
- **可选产物**：宿主支持时，历史细纲摘要作为独立产物（`故事/元数据/细纲摘要_卷X.md`），编剧只读摘要
- **三层叠加**：滚动窗口管剧情方向 + 6 状态文件管世界事实（坑/生死/关系）+ verify.py 管冲突校验（主角位置/生死/关系/持有物冲突即打回）

## 记忆分层读取规则（job-0027补强 · 防止上下文溢出）

### 4层记忆架构

| 层级 | 文件 | 何时读 | 内容粒度 |
|------|------|--------|---------|
| **核心层** | 故事/真相/6文件 + index + 上一章 | **S1/S4 读**（编剧/档案员） | 最新、最短，保证不乱接 |
| **扩展层** | 人物台词卡 + 声线卡 | **S1 读**（压缩进细纲） | 声线规范 |
| **检索层** | hooks.md（伏笔） | **S1 按关键词检索** | 长期档案，不每次全读 |
| **静态层** | anti-ai.md + techniques/*.md | **S1 按需加载**（骨架模板路由） | 参考文档，不入工作记忆 |

> ⚠️ 注意：S2 讲述者**不在任何一层**——它只读细纲产物文件（物理隔离的核心）。

1. ✅ 保存章节正文

4. ✅ 统计有效正文字数
5. ✅ 更新 index.md（当前进度 + 最近三章摘要）
6. ✅ 追加 hooks.md（伏笔新增/回收追踪）
7. ✅ 若人物状态变化 → 更新 characters.md
8. ✅ 若角色话术出现新稳定特征 → 更新声线配置
9. ✅ 展示新章节给用户
10. ✅ **给用户5-8条本章简纲**（承接/行动/冲突/转折/收获/关系变化/章尾钩子）

## 新人误区自检表（job-0033 · 龙空论坛补充）

| # | 误区 | 自检问题 | 修复方向 |
|---|-----|---------|---------|
| 1 | **自嗨陷阱** | 我写的这段，是我自己觉得爽，还是读者会觉得爽？ | 以读者心态重写，不要代入作者视角 |
| 2 | **细节过载** | 这段细节描写是否阻碍了节奏？是否写了两遍同样的信息？ | 删除冗余描写，只保留推动情节的细节 |
| 3 | **配角抢戏** | 配角是否比主角更耀眼？读者会代入谁？ | 降调配角，让主角成为全场焦点 |
| 4 | **速度陷阱** | 前三章细节描写是否太重，导致后面越来越水？ | 前三章保持快节奏，不要沉溺细节 |
| 5 | **拒绝反馈** | 读者/编辑提的意见，我是否完全不听？ | 开放心态，区分"建议"和"批评" |
| 6 | **同质化** | 这个爽点/桥段，是否网上已经有100本书写过？ | 加入自己的稀缺性（角色/方法/世界观差异） |

> **核心原则**：写读者想看的，不是写自己想写的。

## 中断与恢复

如果对话中途断开（compact 或新会话）：
1. 读取最近章节的检验报告 + 细纲恢复上下文（S1 输入）
2. 读取 故事/真相/ 6个状态文件（含 objects/timeline）确认当前状态
