# 模型文档 · 各阶段适用模型与提示策略

> 用途：记录 novel-engine 各阶段适用的模型推荐、提示策略、已知限制与补偿方法。
> 原则：模型是工具，skill 是治理框架。同一个 skill 可以在不同模型上运行，只要正确配置提示。
> 上次更新：2026-09-13（基于skill v1.5.0 链路分析）

---

## 0. 核心原则

**skill ≠ 任何单一模型。** novel-engine 的治理逻辑（verify.py / self-review / anti-ai / PMC suppression）在任何具备足够上下文窗口的模型上都能运行。模型差异影响的是**写作质量上限**和**提示策略**，不是 skill 流程本身。

**模型选择判断树**：

```
用户说"外包"或"用chat写"？
├── 是 → chat-outsource 分支（模板在 templates/outsource-prompt.md）
│       模型由用户选择，skill 负责治理
│
└── 否 → 技能直接跑
        ├── 规划/自检/落库 → 任意模型（流程逻辑，模型无差异）
        └── 正文写作 → 首选豆包（skill 原生适配）
```

## 2. 各模型详细说明

### 2.1 豆包（主力模型）

**适配性**：⭐⭐⭐⭐⭐（最高）

**优势**：
- skill 的全部参考文档（doubao-human-signal / doubao-novel-writing）均基于豆包设计
- editor-perspective / human-signal / prompt-defense 均为豆包原生能力
- 上下文窗口足够容纳完整 skill 链路
- 去AI味（anti-ai / 四大转换）方法论出自豆包

**已知限制**：
- 额度限制（对话额度耗尽后无法继续）
- 长篇写作的上下文溢出风险（skill 的强制加载规则就是为了解决这个问题）
- 写作时可能产出偏"规范"的文字（skill 的去AI味机制专门对治这一点）

**提示策略**：
- **阶段①~⑤**：直接使用 skill 指令，豆包能理解 skill 文件系统
- **写作时**：强制加载声线样本（`素材池/author_dna/`），避免豆包自带的"规范腔"
- **自检时**：强调"读者通道"和"编辑通道"双身份，豆包对角色化指令响应好

**验证经验**：
- E-002 基线测试证明：豆包在 skill 流程下可以产出 full_pass（4/4自检通过）
- B-001 Ch6 模仿写作：4/4 自检通过，evidence_ids 100%真实

---

### 2.2 Claude（外包写作首选）

**适配性**：⭐⭐⭐⭐（写作质量高）

**优势**：
- 写作风格自然，声线保持能力强
- 上下文理解深，不容易产生"规范腔"
- chat-outsource.md 已将其列为首选外包模型

**已知限制**：
- 无法访问本地 skill 文件（outsource-prompt 必须自包含）
- 容易产生"章尾硬收束"（outsource-prompt 模板已强制要求"接续式结尾"）
- 容易忽略"只给本章相关状态"的防剧透要求

**提示策略**：
- **必须使用** `templates/outsource-prompt.md` 模板编译最终提示词
- **身份指令**：明确写"作者身份 + 讲述者口吻"，不用"AI助手"
- **字数限制**：模板中明确字数要求，Claude 倾向于无限延展
- **接续式结尾**：在【写作要求】中强制写"首选取接续式结尾"
- **回接后**：必须走阶段④（去AI味），Claude 稿通常带轻微 AI 味但比豆包轻

---

### 2.3 GPT-4/4o（通用可用）

**适配性**：⭐⭐⭐（可用但需注意）

**优势**：
- 写作能力强，风格多样
- 上下文理解好
- 通用性强

**已知限制**：
- 更容易产生"完美但假"的文字（AI味特征明显）
- 声线保持能力中等，长文容易漂移
- 去AI味的四大转换原则对 GPT 更必要

**提示策略**：
- **阶段②写作**：强制加载 author_dna 声线样本
- **阶段④去AI味**：必须跑完整流程
- **反例**：GPT 擅长生产"看起来对但读起来假"的文字，必须用 anti-ai.md 严格审查

---

### 2.4 其他模型（视能力而定）

**适配性**：⭐⭐（视模型质量）

**通用原则**：
- 任何模型都可以跑 skill 的流程逻辑（verify.py / self-review）
- 写作质量差异主要来自模型的"规范腔"程度
- 越弱的模型越需要强制声线样本和反AI味机制

**使用判断**：
```
模型写出的文字，读起来"像真人写的"吗？
├── 是 → 可直接用
└── 否 → 必须走完整 anti-ai.md 流程
        └── 限制：该模型的上限就是"不太像AI"
```

## 3. 各阶段模型配置建议

### 阶段①（规划）

**推荐**：任意模型均可

**理由**：规划是结构逻辑，模型差异极小。豆包原生适配，但 Claude/GPT 也可以正确执行 session-start.md 的加载清单和输出模板。

**提示要点**：
- 明确输出"阶段①规划清单"的固定格式
- 强制要求加载 6 状态文件（不依赖模型自觉）

---

### 阶段②（正文写作）

**推荐**：豆包（首选）> Claude（外包）> 其他（需治理）

**理由**：正文写作是模型差异最大的环节。声线保持/节奏控制/AI味规避都需要 skill 原生适配。

**自写（豆包）**：
```
skill 直接跑
→ 强制加载 author_dna（声线样本）
→ 规划清单约束写作范围
→ 写完走阶段③④⑤
```

**外包（Claude/其他）**：
```
技能编译 outsource-prompt
→ 用户贴入外部 chat
→ 正文贴回
→ 技能走阶段③自检（必须 evidence_ids）
→ ④去AI味（必须跑满，外部稿几乎必带AI味）
→ ⑤落库
```

---

### 阶段③（自检）

**推荐**：豆包（原生）> Claude > 其他

**理由**：自检依赖"读者先读、编辑再审"的双通道，豆包对角色化指令响应最好。Claude 的批评能力也强，但需要明确的自检模板。

**提示要点**：
- 使用 self-review.md 的固定报告模板
- 强制要求 evidence_ids（verify.py 的 scope=evidence 会检查）
- 4问必须全部回答，不能跳过

---

### 阶段④（去AI味）

**推荐**：豆包（原生）> Claude > GPT（需严格）> 其他（限制）

**理由**：去AI味的四大转换原则（anti-ai.md）来自豆包方法论，豆包最清楚如何执行。其他模型需要更明确的示例引导。

**提示要点**：
- 按成因层定位（观点/结构/表达/素材/叙事/情感/语境）
- AI味指数高（>60）时必须系统性修复
- 改完必须通读（"若更难读/更啰嗦/更失焦，回退"）

---

### 阶段⑤（落库）

**推荐**：任意模型

**理由**：落库是文件操作逻辑，模型差异最小。

---

## 4. 模型限制补偿速查

| 模型 | 主要限制 | 补偿方法 |
|------|---------|---------|
| 豆包 | 额度耗尽 | 交接文档（state export）+ 另一模型接手 |
| 豆包 | 上下文溢出 | skill 强制加载规则（只读必要文件） |
| Claude | 无法读本地文件 | outsource-prompt 自包含模板 |
| Claude | 章尾硬收束 | 模板强制"接续式结尾"指令 |
| GPT | 规范腔/AI味重 | 强制 author_dna + anti-ai 四问 |
| 任意弱模型 | 声线漂移 | author_dna 声线样本强化注入 |

---

## 5. 模型切换时的交接规范

**豆包额度耗尽 → 切换豆包/Claude**：
1. 导出当前状态：`故事/真相/` 6文件 + `故事/元数据/` + `novel-config.json`
2. 新模型读取：加载导出文件 + skill 路由
3. 确认：检查 hooks.md（有无超10章伏笔债务）+ timeline.md（时间线是否连续）
4. 继续：从阶段①规划下一章开始

**外包稿回接**：
```
1. 检查：YAML残留 / 声线偏离 / 缺节点
2. 自检：4问全跑 + evidence_ids（verify.py scope=evidence）
3. 去味：anti-ai.md 全流程
4. 落库：Change Report + 6状态文件
```
