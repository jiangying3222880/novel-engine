# 阶段①：项目启动与本章规划 SOP

## 1. 状态装载流程

在回答用户前，按顺序读取且仅读取以下文件：

### 强制加载（必须全部读取）

1. `story/truth/characters.md` — 角色基线摘要 + 当前状态（位置/情绪/知识/携带物品）
2. `story/truth/world.md` — 世界核心规则 + 当前状态（时间/地点/环境/大事记）
3. `story/truth/hooks.md` — 当前生效的伏笔与未解悬念
4. `story/truth/relationships.md` — 角色关系网络

### 基础信息

5. `novel-config.json` — 项目档案（书名/题材/字数/基调）
6. 最新已完成章节的 Frontmatter — 上一章的 causal_links / hooks / emotion_arc / change_summary

### 按需读取（本章涉及才读）

7. `设定/角色声线.md` — 仅当有新角色或声线存疑时才读完整档案
8. `设定/世界观.md` — 仅当涉及新设定或设定存疑时才读完整档案
9. `pools/author_dna/` 主对标书DNA — 风格校准（推荐读）
10. `pools/planner/` 对应卷结构 — 节奏校准（推荐读）
11. `pools/reference/techniques/` 对应技巧 — 方法论参考（按场景选1-2个）
12. `pools/reference/samples/` 同类场景 — 实战样本参考（按场景选1-2个）

**首次启动判断**：如果项目目录中没有 `novel-config.json`，说明项目未初始化，跳转至 `references/00-project-setup.md` 执行阶段⓪。

**禁止全量加载设定集。** 大纲文件只读当前章对应段落。

## 3. 新角色检查

判断本章是否有首次出场的说话角色：
- **有新角色** → 按 `templates/voice-profile-template.md` 建立完整基线档案，写入 `设定/角色声线.md` + 更新 `story/truth/characters.md` 基线摘要
- **无新角色** → 直接使用已有基线

## 4. 章态注入

为本章每个出场角色生成 3-4 行声线章态：

```
角色名｜当前情绪状态｜语言节奏变化（vs基线）｜口癖/习惯变化｜动作泄露
```

**章态必须落在基线的情绪光谱内。** 超出光谱 = OOC。

---

## 4.5 状态冲突优先级

当多个状态文件给出的约束互相矛盾时（例如：角色基线说"冷静克制"，但本章状态是"巨大悲痛"），按以下优先级裁决：

```
第1级：世界不可变规则（story/truth/world.md → 核心规则）
    ↓
第2级：角色硬边界（story/truth/characters.md → 基线摘要 → 硬边界）
    ↓
第3级：角色核心性格（story/truth/characters.md → 基线摘要 → 语言基线+情绪光谱）
    ↓
第4级：本章章态（chapter-state）
    ↓
第5级：临时剧情需求
```

**裁决原则：**
- 低级状态不能突破高级状态的边界
- 例：角色基线"不会长篇说教"（第2级硬边界）> 本章章态"情绪激动话多"（第4级）→ 激动时可以话变多，但仍然不会说教
- 例：世界规则"意识上传不可逆"（第1级）> 任何角色决策（第5级）→ 角色不能因为剧情需要就突然能逆转上传

**冲突时的处理方式：**
1. 先确认是否真的矛盾（有时候是理解错了）
2. 确实矛盾的，低级让位于高级
3. 如果高级约束导致本章剧情走不下去 → 说明规划有问题，需要调整本章事件，而不是突破高级约束
4. 如果高级约束本身需要修改 → 那是世界观/角色设定的变更，必须在阶段⑤通过 Change Report 正式更新，不能在写作阶段临时突破

## 5. 规划判断逻辑
