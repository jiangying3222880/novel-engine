# 阶段⓪：项目初始化与导入

本文件在五阶段 SOP 之前执行。判断走入口 A（从零创建）还是入口 B（导入已有），完成后进入阶段①。

---

## 入口判断

| 用户指令 | 路由 |
|---------|------|
| "我想开一本新书""帮我建项目""开始写新书" | → 入口 A |
| "我有设定/大纲/角色，帮我导入""把已有项目导进来" | → 入口 B |
| 已有 novel-config.json 且用户说"写第X章" | → 跳过⓪，直接进① |

---

## 入口 A：从零创建（对话驱动）

通过对话逐步建立项目文件。每步完成后确认再进下一步。

### Step 1：作品基础信息

向用户提问以下内容（用户回答后整理为 novel-config.json）：

1. **书名**：暂定也行
2. **题材**：科幻/玄幻/都市/末日/历史/其他
3. **叙述视角**：第三人称限知 / 第一人称 / 全知 / 多POV
4. **每章目标字数**：2000/3000/4000/6000/其他
5. **基调**：冷峻紧凑 / 轻松幽默 / 热血燃向 / 阴暗压抑 / 其他
6. **预计总章数**：心里有数就填，没有就留空

完成后生成：
```
novel-config.json
```

### Step 2：世界观与核心设定

向用户提问引导（不要一次问太多，分轮对话）：

1. **故事发生在什么地方？** → 提取地理/社会环境
2. **核心矛盾是什么？** → 提取主线冲突（人vs人/人vs环境/人vs自我）
3. **有没有特殊设定？** → 提取力量体系/科技层级/社会规则
4. **时间跨度多大？** → 提取故事时间线（几天/几年/几代人）

用户回答后，Agent 整理为结构化文档：
```
设定/世界观.md
```

格式：
```markdown
# 世界观设定

## 地理/社会环境
[整理用户描述]

## 核心矛盾
[一句话主线 + 展开]

## 特殊设定
[力量体系/科技/规则，逐条列]

## 时间线
[故事跨度 + 关键节点]
```

### Step 3：角色建立

对每个主要角色（建议先建3-5个核心角色），通过对话获取：

1. **名字和身份**：谁？干什么的？
2. **核心性格**：用3个词形容
3. **说话方式**：话多还是话少？用词偏文还是偏俗？有没有口头禅？
4. **不会做的事**：这个角色绝对不会怎样？（硬边界）
5. **压力下怎么变**：紧张时说话会变成什么样？

Agent 按 `templates/voice-profile-template.md` 格式整理为：
```
设定/角色声线.md
```

每个角色包含：核心身份、语言基线、硬边界、情绪光谱、典型口癖、动作泄露。

### Step 4：大纲搭建

分两级建立：

**卷纲**（先建）：
```
大纲/卷纲.md
```
向用户提问：
1. 这本书分几卷？
2. 每卷的核心事件和情绪走向是什么？

格式：
```markdown
# 卷纲

## 第一卷：[卷名]
- 核心事件：[一句话]
- 情绪走向：[起点] → [终点]
- 预计章数：[X章]

## 第二卷：[卷名]
...
```

**细纲**（逐章建，至少先建前3章）：
```
大纲/细纲_第1章.md
大纲/细纲_第2章.md
大纲/细纲_第3章.md
```

每章细纲格式：
```markdown
# 第X章细纲：[章名]

## 核心事件
[一句话]

## 出场角色
- [角色A]：[本章状态]
- [角色B]：[本章状态]

## 场景序列
1. [场景1]：[发生什么]
2. [场景2]：[发生什么]

## 情绪弧
[起点] → [终点]

## 伏笔计划
- 埋：[Hook内容]
- 收：[Hook ID]（如有）
```

### Step 5：初始化伏笔库

```
hooks.md
```

内容：
```markdown
# 伏笔追踪库

（第1章写作后开始记录）
```

### Step 6：确认并进入写作

检查所有文件：
```
novel-config.json      ← 项目档案 ✓
设定/世界观.md          ← 世界观 ✓
设定/角色声线.md        ← 角色基线 ✓
大纲/卷纲.md            ← 卷纲 ✓
大纲/细纲_第1章.md      ← 第1章细纲 ✓
hooks.md               ← 空伏笔库 ✓
```

确认后对用户说："项目初始化完成，现在开始写第1章"，进入阶段①。

## 入口 B：导入已有（映射驱动）

用户提供已有文件（设定/大纲/角色/正文），Agent 读取并映射到标准结构。

### Step 1：收集已有材料

向用户确认有哪些文件：
- 世界观设定文档？
- 大纲文档？（卷纲/分章纲/完整细纲）
- 角色设定文档？
- 已写正文？（半成品续写）
- 伏笔/设定追踪文档？

用户提供文件路径后，Agent 逐个读取。

### Step 2：映射到标准结构

**世界观 → `设定/世界观.md`**
- 如果已有世界观文档：直接复制或重新整理为标准格式
- 如果散落在正文/大纲中：提取关键设定整理成文档

**大纲 → `大纲/` 目录**
- 已有卷纲 → `大纲/卷纲.md`
- 已有分章细纲 → 每章存为 `大纲/细纲_第N章.md`
- 只有一个总大纲 → 拆分为卷纲 + 逐章细纲（Agent 辅助拆解）
- 没有大纲 → 提示用户"建议先建至少前3章细纲"，或对话快速建立

**角色 → `设定/角色声线.md`**
- 已有角色设定：提取语言习惯/口癖/性格 → 按声线模板补全4维度
- 仅有角色描述（外貌/背景/性格词）：Agent 根据描述推断语言基线，标注"推断项，待实测修正"
- 缺少硬边界和情绪光谱：Agent 补充建议，用户确认

**正文 → `正文/` 目录**
- 已有正文：保持原文件，为每章补 Frontmatter（chapter_id/causal_links/hooks/emotion_arc）
- 无正文：跳过

**伏笔 → `hooks.md`**
- 已有伏笔追踪：映射为三态格式（[active]/[closed]/[abandoned]）
- 无伏笔追踪：扫描已有正文，提取埋设的伏笔，建立 hooks.md
- 无正文：初始化空 hooks.md

### Step 3：生成 novel-config.json

从已有材料推断：
- project_name：从大纲/正文标题提取
- genre：从世界观/大纲判断
- perspective：从正文叙述视角判断
- target_word_count：从已有正文章节均字数推断
- tone：从正文语言风格推断
- chapters_completed：已有正文章节数

推断不确定的字段标注 `[待确认]`，请用户确认。

### Step 4：确认并进入写作

输出项目状态摘要：
```markdown
### 项目导入完成

- 书名：[X]
- 题材：[X]
- 已有章节：[X] 章
- 角色基线：[X] 个角色已建立
- 伏笔追踪：[X] 个 active / [X] 个 closed
- 下一章：第 [X] 章

现在开始写下一章？
```

确认后进入阶段①，从下一章开始五阶段 SOP。

---

## 两个入口的共同规则

1. **不写正文**：阶段⓪只建项目文件，不写任何正文。正文从阶段①开始。
2. **对话分轮**：不要一次性问完所有问题，每轮2-3个问题，用户回答后再问下一批。
3. **用户可跳过**：任何步骤用户说"先不弄"都可以跳过，后续随时补。
4. **文件即落盘**：每步完成后立即写入文件，不要全部对话完再一次性写。
