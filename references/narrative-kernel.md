# 叙事内核（Narrative Kernel · 冻结版）

> 来源：`F:\炼丹计划\03_core\narrative-core.md`（炼丹炉唯一宪法）
> 性质：**冻结内核不可修改**（L0/L1 修改必须走 Core Change Proposal + 用户批准）
> 编译方式：内核 → 本文件的"Agent 执行落点"（规划强制项 / 自检问题 / 机器门禁）

## 0. 一句话内核

**套路可以变化，支撑"故事成立"的底层关系不会随题材消失。**

本引擎不建立在"小说套路"上，建立在**叙事因果与变化机制**上。套路 = 内核在不同市场/题材/篇幅下的参数化表现。

## 1. Story Causality Loop（最小循环）

```
目标 → 行动 → 阻力 → 选择 → 结果 → 状态变化 → 新目标 → 下一事件
```

**因果是循环的性质，不是独立规则。** 事件不是"然后A然后B"，而是"A改变了条件 → 角色因此选择 → 选择产生B → B又改变条件"。

**诊断用法**：规划/自检时，把本章剧情套进这个循环。任何一个环节缺失（无目标/无阻力/选择无后果），就是注水或流水账的病灶。

## 2. 冻结内核表（L0 铁律 + L1 原则）

| ID | 层级 | 内核 | 表述（冻结版） | 反例判定 |
|----|------|------|--------------|---------|
| **C-001** | L0 | 目标存在不可变 | 人物必须有目标；目标形态可变（追求/解脱/离开/毁灭）；"摆烂"是目标伪装 | 摆烂流=表面反例（底层仍是"解脱/回家"目标） |
| **C-002** | L0 | 行动产生后果 | 选择必须改变状态（信任/关系/资源/认知/处境），否则注水 | 躺赢流=合法变体（"不行动"是选择，后果可追踪） |
| **C-006** | L0 | 证据链根基 | 任何自检/判断/建议必须带可追溯证据（evidence_ids），无证据的"通过/建议"无效 | 无原文复核的机器结论全错（job-0002 实证） |
| **C-005** | L1 | 状态唯一真相源 | 故事状态必须集中在单一真相源（SSOT），不在正文/提示词/对话散存 | — |
| **C-007** | L1 | Guidance 引导 | 系统对"怎么写"只提供证据化引导不设硬约束；硬规则只用于流程执行层 | — |
| **C-003** | L1 | 信息三层错位 | 事实≠角色知道≠读者知道，是悬疑/误会/反转/伏笔根源。**错位方向可因类型而变（读者侧/反派侧/意识侧），但三层差异不可消除** | 爽文透明/冰山/意识流=表面反例（信息差方向反转/主动省略/过滤层） |
| **C-004** | L1 | 冲突是引擎 | 张力来自欲望与阻力的对抗；阻力=人/制度/时间/信息/性格/资源/环境。**冲突含隐性形态（欲望内化/信息不可得/物化隔阂），不限于外部冲突** | 《嫉妒》物化=表面反例（欲望内化仍在驱动）；纯静物滑出叙事范畴 |
| **C-008** | L1 | 高潮必经过程 | 高潮必须经过充分“过程”（量变→质变），无过程的高潮突兀无力；开头可先小高潮抓人（网文浅阅读特例） | 意识流/实验文学=受控违反（作者有意打破）；网文开头小高潮=表面反例（总高潮前奏） |

> **三块 L0 地基自洽**：C-002 管"必须有变化"，C-006 管"怎么证明变化"，C-001 管"变化的驱动力是什么"。

## 3. 编译落点：Agent 执行时怎么强制这些内核

### 3.1 阶段①规划 · 内核三联（写前强制）

每章规划清单必须显式输出 **内核三联**，缺一项 = 规划不完整，禁止进入阶段②：

```
内核三联（写前必填）：
  [目标] 本章主角想要什么？为什么现在想要？（C-001）
  [阻力] 什么阻碍他？属于哪类阻力（人/制度/时间/信息/性格/资源/环境/隐性）？（C-004）
  [后果] 他采取行动后，什么状态会改变？（信任/关系/资源/认知/处境）（C-002）
```

> 这就是 Story Causality Loop 的压缩版。写前三问，防止无目标漂移、无阻力流水账、无后果注水。

### 3.2 阶段①规划 · Hook 计划 = 信息差设计（C-003）

Hook 计划不只是"埋个悬念"，要显式标注**信息差方向**：

```
本章信息差设计：
  [读者侧藏] 读者不知道什么？（悬念/反转用）
  [反派侧藏] 读者知道但反派/配角不知道？（爽文/误会用）
  [意识侧藏] 叙述者过滤了什么？（意识流/隐晦用）
```

> 三层差异不可消除，但方向可换。悬疑靠读者侧藏，爽文靠反派侧藏，伏笔靠"埋了但不揭"。

### 3.3 阶段③自检 · 内核追加 2 问（C-001/C-002）

在现有 4 问之外，追加（或并入 Q2/Q4）：

```
内核自检追加：
  [目标可读吗] 读者能否从正文中"看见"主角目标（不是作者知道，是文本呈现）？（C-001）
  [变化可证吗] 本章末尾，至少一个状态发生了可观察的变化？引用原文证明？（C-002）
```

### 3.4 阶段⑤落库 · Change Report = C-002 的机制化

Change Report 本身就是 C-002 的执行保障：**每个"变化"必须登记到 6 状态文件**。如果 Change Report 是空的（什么都没变），这章就是注水章，打回。

### 3.5 机器门禁 · verify.py 已覆盖的内核

| 内核 | verify.py 检查项 |
|------|-----------------|
| C-005（SSOT） | [数据层防污染] 真相/元数据禁双链；[config合法性] 单配置源 |
| C-006（证据链） | 无（证据链是 LLM 自检语义，程序无法判，靠 self-review 强制） |

> 边界：verify.py 是校验器不是执行器；C-001/002/003/004 是语义判断，程序做不了，靠"规划强制项 + 自检问题 + 落库门禁"三处压。

## 4. 内核 vs 技法（防止"把技法当内核"）

| 层 | 是什么 | 例子 | 能否改 |
|----|--------|------|--------|
| L0 内核 | 叙事结构性必然 | C-001 目标 / C-002 后果 / C-006 证据 | 冻结，不可动 |
| L1 原则 | 跨类型成立的核心机制 | C-003 信息差 / C-004 冲突 / C-005 SSOT / C-007 Guidance | 冻结，CCP+用户批准才可改 |
| L2 技法 | 题材/篇幅策略 | 断章未闭合感（丹核004）、憋压三段式、身份逆转反转法 | 可替换 |
| L3 表达 | 怎么写 | anti-ai 四大转换、对话不对称 | 可调整 |
| L4 策略 | 平台/商业 | 钩子密度按题材（38%-70%）、上架掐高潮 | 随生态变 |

**判断问题：加一个新规则前，先问它支撑哪条内核？答不出 = 不加入（避免知识堆砌）。**

## 5. 短故事分支的内核适配

短故事（8000-30000，三段式憋压爆发）同样受内核约束，只是落点不同：
- C-001：憋压型主角的"目标"= 忍到爆发（解脱/反击是深层目标）
- C-002：中段憋压靠"处境持续恶化"累积（后果未完成 = 未闭合感）
- C-003：信息差方向 = 读者侧藏（"他到底什么时候爆发"）
- C-004：阻力全程压着不释放，直到结尾一次性宣泄
- C-008：中段憋压 = 高潮的“过程”（量变→质变），爆发 = 过程终点；憋压层数不足 5 层 = 过程不充分，爆发无力

> **驱动标注 = 内核的读者侧落点（v1.7）**：写前必填 4 字段（制造什么期待/第几段引爆/憋到什么程度给/读者翻页动力）本质上是把 C-001（读者追踪目标）、C-002（读者追踪变化）、C-003（读者侧信息藏）翻译成"读者为什么停不下来"的可执行承诺。驱动标注是执行层工具（L2），不新增内核，只是把冻结内核编成写前必填项。
