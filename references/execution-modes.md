# 执行模式与子 Agent 隔离（Execution Modes · v1.8）

> 定位：流程层文件（L2）。解决"三层架构的中间层如何隔离上下文"与"有降级手段时如何防偷懒"。
> 上游：SKILL.md 模块路由表 · `references/workflow-detail.md` 阶段②三条硬指令
> 下游：阶段②写作执行 · 流程日志（`故事/日志/`）· verify.py（execution_mode 字段校验）

---

## 0. 一句话

**状态全在文件系统，交接物全落盘 → 窗口切换零损失。** 隔离手段可以降级（多窗口→单窗口），**交付物与门禁不降级**。

---

## 1. 三档执行模式

| 档位 | 含义 | 何时用 |
|------|------|--------|
| **auto**（默认） | 启动时能力探针：宿主有子 Agent/spawn 能力 → 多窗口；无 → 降级单窗口（显式声明） | 用户未指定时 |
| **single** | 强制单窗口：写作/自检/润色在同一窗口内完成，用三条硬指令模拟隔离 | 用户指定 / 宿主无子 Agent 能力 / 简短任务 |
| **multi** | 强制多窗口：阶段①③④⑤由独立子 Agent 执行，各窗口只读自己的输入 | 用户指定（大章节/长文本/需要严格隔离时） |

**用户显式指定 multi 但宿主无能力** → 明确报错提示改 auto/single，**不静默降级**。
**用户显式指定 single** → 即使有能力也按 single 执行（用户选择），日志记录"用户指定"。

---

## 2. 子 Agent 隔离：内容传递与状态同步

### 2.1 交接物 = 固定命名的标准产物文件（不是会话内传递）

| 阶段 | 产物文件（落盘） | 谁写 | 谁读 |
|------|----------------|------|------|
| ① 规划 | `故事/元数据/规划_第000X章.md`（规划清单+内核三联+驱动标注+章态+**待落库变更请求**） | 规划 Agent | 写作 Agent |
| ② 写作 | `正文/第000X章 <标题>.md` | 写作 Agent | 自检 Agent |
| ③ 自检 | `故事/元数据/自检_第000X章.md`（报告+evidence_ids） | 自检 Agent | 润色 Agent |
| ④ 润色 | 精修稿（覆盖正文文件） | 润色 Agent | 落库 Agent |
| ⑤ 落库 | Change Report + 6 状态更新 + 元数据/index + 索引 | 落库 Agent | — |

子 Agent 各自完成后**即落盘**；下一个子 Agent **启动时重新读盘**，不依赖上一个 Agent 的任何会话内存。

### 2.2 truth 写入唯一窗口 = 阶段⑤（防并发写冲突）

- 规划 Agent 发现新角色/新伏笔/关系变化 → **不直接改 truth**，写入规划文件的"待落库变更请求"区
- 落库 Agent 按 Change Report + 待落库请求**统一执行**（符合 C-005 SSOT + 现有 Change Report 机制）
- 写作/自检/润色 Agent 对 6 状态文件**只读**，全程不写

### 2.3 产物链校验

规划→正文→自检→精修→落库形成一条链，每个产物文件头带章节号+阶段标记。verify.py 检查链条完整性：**缺一环 = 流程未完成，禁止交付**。

## 3. 防偷懒降级（三道闸）

> 风险：auto 模式下 Agent 谎报"无子 Agent 能力"直接走 single（省事、不切换上下文）。三道闸把降级变成"显式、可查、不减工"。

### 3.1 闸一：降级不靠自报，靠能力探针

**禁止问自己"有没有子 Agent 能力"**（会答没有）。改为确定性检查：

1. 列出当前宿主**工具清单**（客观存在性，非自评）
2. 清单中**存在** spawn/子 Agent/多 Agent 协作类工具 → 有能力，auto 下**必须**走多窗口
3. 清单中**确实没有**该类工具 → 才可降级 single
4. 探针结果写入流程日志（见 3.2）

> 判定依据是"工具清单里有没有"，不是"我觉得麻烦"。工具清单是宿主给的客观事实，Agent 无法自报。

### 3.2 闸二：降级必须显式声明 + 留痕

每次降级（或用户指定档位）在 `故事/日志/第000X章.md` 写一行：

```
execution_mode=auto，探针结果：宿主工具清单无 spawn/子 Agent 工具，降级 single；隔离手段变更，交付物与门禁不减。
```

- 不声明 = 流程未完成（verify.py 检查该字段）
- 用户指定 single/multi 也记录（"用户指定"与"探针降级"分开标注）
- 交付时用户可见：这一章用什么模式写的、为什么

### 3.3 闸三：降级 ≠ 减工，门禁不减

single 模式用 workflow-detail 阶段②三条硬指令（角色重锚定/输入最小化/禁读清单）在单窗口内模拟隔离。**阶段产物、自检、evidence_ids、Change Report、6 状态更新一个不少**——降级只改变"上下文怎么隔离"，不改变"必须交付什么"。

## 4. single 模式的隔离机制（注意力管理）

无物理隔离时，用三条硬指令在单窗口内划出"写作窗口"：

| 硬指令 | 做法 | 防什么 |
|--------|------|--------|
| 角色重锚定 | 动笔前声明"以下仅讲述者身份产出，因果循环/内核三联/模块调度视为已完成背景" | 编剧/编辑身份抢讲述者的戏（框架显形） |
| 输入最小化 | 只带"内核三联一行+本章关键状态行"进写作窗口；规划全文/状态全文留盘上 | 上下文污染（多带=多干扰） |
| 禁读清单 | 阶段②不 Read anti-ai.md / self-review.md / short-story.md / module-registry.md 全文 | 写后工具提前拉进写作窗口（边写边自检） |

---

## 5. 与 L3 模块的关系

- 执行模式只决定"**同一个阶段**的上下文隔离方式"，不改变"**哪个阶段该加载哪个 L3 模块**"（后者归 `module-registry.md` 调度）
- 多窗口下，子 Agent 启动时按模块路由表决定自己窗口内读不读 L3 模块卡；single 下同规则
- 模块触发/挂载铁律见 SKILL.md 模块路由表 + `references/module-registry.md`
