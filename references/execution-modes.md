# 执行模式与物理隔离（Execution Modes · v1.9）

> 定位：流程层文件（L2）。解决"S1-S4 流水线如何物理隔离上下文"与"有降级手段时如何防偷懒"。
> 上游：SKILL.md 模块路由表 · `references/workflow-detail.md`（S1-S4 流水线全文）
> 下游：S2 写作执行 · 流程日志（`故事/日志/`）· verify.py（execution_mode 字段校验 + 产物链完整性）

---

## 0. 一句话

**状态全在文件系统，交接物全落盘 → 窗口切换零损失。** 隔离手段可以降级（multi→single），**交付物与门禁不降级**。

**⚠️ 物理隔离 vs 模拟隔离（v1.9 关键区分）**：
- **multi = 物理隔离**：讲述者 Agent 在独立子窗口，物理上看不到规则文本/状态文件/技法库，只读细纲产物文件。这是真隔离。
- **single = 模拟隔离**：同一窗口内，三条硬指令模拟隔离。**物理隔离不成立**——Agent 仍带着之前对话历史。三条硬指令是 single 专用降级方案，不是隔离的替代品。

---

## 1. 三档执行模式

| 档位 | 含义 | 何时用 |
|------|------|--------|
| **auto**（默认） | 启动时能力探针：宿主有子 Agent/spawn 能力 → multi（物理隔离）；无 → 降级 single（显式声明 + 降级声明记录） | 用户未指定时 |
| **single** | 强制单窗口：S1-S4 在同一窗口内完成，用三条硬指令模拟隔离 | 用户指定 / 宿主无子 Agent 能力 / 简短任务 |
| **multi** | 强制多窗口：S1 编剧 / S2 讲述者 / S3 检验 / S4 档案员由独立子 Agent 执行，各窗口只读自己的输入 | 用户指定（大章节/长文本/需要严格隔离时） |

**用户显式指定 multi 但宿主无能力** → 明确报错提示改 auto/single，**不静默降级**。
**用户显式指定 single** → 即使有能力也按 single 执行（用户选择），日志记录"用户指定"。

## 2. 物理隔离：内容传递与状态同步（multi）

### 2.1 交接物 = 固定命名的标准产物文件（不是会话内传递）

| 阶段 | 产物文件（落盘） | 谁写 | 谁读 |
|------|----------------|------|------|
| S1 骨架 | `故事/元数据/细纲_第XXXX章.md`（四维骨架） | 编剧 Agent | 讲述者 Agent + 检验 Agent + 档案员 |
| S2 血肉 | `正文/第000X章 <标题>.md` | 讲述者 Agent | 检验 Agent |
| S3 检验 | `故事/元数据/检验报告_第XXXX章.md`（双视角） | 检验 Agent | 档案员 Agent |
| S4 落库 | Change Report + 6 状态更新 + `故事/日志/第XXXX章.md` | 档案员 Agent | 下一章 S1 |

子 Agent 各自完成后**即落盘**；下一个子 Agent **启动时重新读盘**，不依赖上一个 Agent 的任何会话内存。

### 2.2 S2 写作输入包（物理最小 · multi）

讲述者 Agent 启动时**只读**：
```
故事/元数据/细纲_第XXXX章.md（唯一强制输入）
novel-config.json（仅 target_word_count + body_dir）
```
**禁止读取**：6 状态文件、writing-guide.md、anti-ai.md、self-review.md、技法库全文、素材池全文。
声线信息已在细纲 §5（透传自角色卡），知识边界已在细纲 §6（角色状态最小摘要）——讲述者不需要原始文件。

### 2.3 truth 写入唯一窗口 = S4（防并发写冲突）

- S1 编剧发现新角色/新伏笔/关系变化 → **不直接改 truth**，写入细纲"待落库变更请求"区
- S4 档案员按 Change Report + 待落库请求**统一执行**（符合 C-005 SSOT + 现有 Change Report 机制）
- S2/S3 对 6 状态文件**只读**，全程不写

### 2.4 产物链校验

细纲→正文→检验报告→落库形成一条链，每个产物文件头带章节号+阶段标记。verify.py 检查链条完整性：**缺一环 = 流程未完成，禁止交付**。

## 3. single 模式隔离机制（模拟隔离 · 降级专用）

无物理隔离时，用三条硬指令在单窗口内划出"写作窗口"：

| 硬指令 | 做法 | 防什么 |
|--------|------|--------|
| 角色重锚定 | 动笔前声明"以下仅讲述者身份产出，因果循环/内核三联/模块调度视为已完成背景" | 编剧/编辑身份抢讲述者的戏（框架显形） |
| 输入最小化 | 只呈现细纲_第XXXX章.md 内容 + 目标字数进写作；细纲全文在盘上，不复制规则/状态/技法文本 | 上下文污染（多带=多干扰） |
| 禁读清单 | 不 Read anti-ai.md / self-review.md / short-story.md / module-registry.md 全文 | 写后工具提前拉进写作窗口（边写边自检） |

> ⚠️ **三条硬指令是 single 模式专用降级方案**（v1.8 的 ⑩ 保留改定位，不删除）。multi 物理隔离成立时不需要它们——物理上看不到比声明"看不到"可靠。

## 4. 防偷懒降级（三道闸）

> 风险：auto 模式下 Agent 谎报"无子 Agent 能力"直接走 single（省事、不切换上下文）。三道闸把降级变成"显式、可查、不减工"。

### 4.1 闸一：降级不靠自报，靠能力探针

**禁止问自己"有没有子 Agent 能力"**（会答没有）。改为确定性检查：

1. 列出当前宿主**工具清单**（客观存在性，非自评）
2. 清单中**存在** spawn/子 Agent/多 Agent 协作类工具 → 有能力，auto 下**必须**走 multi
3. 清单中**确实没有**该类工具 → 才可降级 single
4. 探针结果写入流程日志（见 4.2）

> 判定依据是"工具清单里有没有"，不是"我觉得麻烦"。工具清单是宿主给的客观事实，Agent 无法自报。

### 4.2 闸二：降级必须显式声明 + 留痕

每次降级（或用户指定档位）在 `故事/日志/第XXXX章.md` 写一行：

```
execution_mode=auto，探针结果：宿主工具清单无 spawn/子 Agent 工具，降级 single；隔离=声明级最小化（三条硬指令），非物理隔离；产物与门禁不减。
```

- 不声明 = 流程未完成（verify.py 检查该字段）
- 用户指定 single/multi 也记录（"用户指定"与"探针降级"分开标注）
- 交付时用户可见：这一章用什么模式写的、为什么

### 4.3 闸三：降级 ≠ 减工，门禁不减

single 模式用三条硬指令在单窗口内模拟隔离。**阶段产物、细纲门/正文门、evidence_ids、Change Report、6 状态更新一个不少**——降级只改变"上下文怎么隔离"，不改变"必须交付什么"。

### 4.4 降级声明记录（D-214 措辞修正）

- **multi = 隔离证据链**：输入包落盘存档（细纲+检验报告引用），证明物理隔离成立
- **single = 降级声明记录**：落盘证明只证明"Agent 声明了输入是细纲"，**证明不了物理上只看到细纲**（同一窗口仍带历史）。文档诚实说明：声明 ≠ 隔离

## 5. 与 L3 模块的关系

- 执行模式只决定"**同一个阶段**的上下文隔离方式"，不改变"**哪个阶段该加载哪个 L3 模块**"（后者归 `module-registry.md` 调度）
- multi 下，子 Agent 启动时按模块路由表决定自己窗口内读不读 L3 模块卡；single 下同规则
- 模块触发/挂载铁律见 SKILL.md 模块路由表 + `references/module-registry.md`
