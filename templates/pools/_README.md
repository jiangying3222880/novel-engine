# Pools — 素材池总览（项目级）

**池子是拆解出来的，不是建出来的。空池子没有价值。**

本目录是**当前项目的素材池**，与项目共生。对标书拆解、写作积累的内容都存在这里。跨项目不共享。

---

## 为什么要有池子

AI 写作最大的问题是"风格漂移"和"情节套路化"。池子的作用是：

1. **风格锚定**：Author DNA 让句式/节奏/词汇保持一致
2. **事件参考**：Unit Pool 让你写任何事件都有现成的"好写法"可以对标
3. **结构模板**：Planner Pool 让卷纲/章节节奏有成熟作品的结构打底
4. **场景素材**：Reference Pool 让同类场景的写法直接可借鉴
5. **知识储备**：Knowledge Pool 把对标书里用到的专业知识提前存好，不用临时查

---

## 拆解成本（很重要，先想清楚）

| 拆解项目 | 时间投入 | 产出价值 |
|----------|----------|----------|
| 选3本对标书 | 30分钟 | ★★★ |
| 拆1本 Planner（卷结构） | 1-2小时 | ★★★★★ |
| 拆1本 Author DNA（风格） | 30-60分钟 | ★★★★ |
| 拆1本 Unit（前10章事件） | 2-4小时 | ★★★★ |
| 拆1本 Reference（精选段落） | 1-2小时 | ★★★ |
| 拆1本 Knowledge（知识点） | 30分钟 | ★★ |

**拆1本对标书的总投入：约 5-10 小时**（取决于拆多细）

> 建议：至少拆 3 本（结构 + 文笔 + 节奏各一本），但第一本可以先拆细，后面两本只拆核心部分。

## 入池深度档位（影响token消耗）

| 档位 | 包含内容 | 预估额外token/章 | 适合阶段 |
|------|----------|-----------------|----------|
| 轻量 | Planner + Author DNA | 2-3KB | 刚开始写、预算有限 |
| 标准 | 以上 + Reference 精选段落 | 4-6KB | 稳定写作中 |
| 全量 | 五项全拆 | 8-12KB | 追求极致质量 |

> 池子内容在初始化时一次性拆解完成，后续写作中不自动增长。如后续需要补充新的对标书，手动添加即可。

---

## 五个池子的分工

| 池子 | 存什么 | 什么时候用 | 组织方式 |
|------|--------|-----------|----------|
| `unit/` | 事件单元（拆成原子的关键场景） | 写某类事件前参考 | 按来源分目录：`_source_书名/` + `_self_原创/` |
| `author_dna/` | 作者写作习惯（句式/节奏/词汇） | 写作全程保持风格一致 | 每本书一份DNA |
| `knowledge/` | 对标书用到的事实知识 | 涉及特定领域时取用 | 按领域分文件 |
| `reference/` | 写作技巧 + 精选段落 | 写同类场景时调取参考 | techniques（方法论） + samples（实战样本） |
| `planner/` | 结构决策（卷结构/伏笔编排/情绪曲线） | 规划全书/卷结构时参考 | 每本书一份结构分析 |

## 入池原则（非常重要）

### 1. 只放对标书拆解的高质量内容
池子的价值在于"质量上限"——只放经过市场验证的对标书内容。自己写的稿件无论怎么修改，质量上限低于对标书，入池反而拉低平均水平，导致越写越平庸。

> 如果某段自己写得特别好、想保留参考，直接在章节正文里标备注即可，不必入池。

### 2. 池子是静态的，写作期不自动增长
对标书拆解在项目初始化阶段完成（或分阶段补），写作过程中池子不自动增长。需要补充新的对标书时手动添加。

### 3. 按需加载，不常驻
池子文件量大，写作时只调取当前需要的部分。强制加载的只有 `story/truth/` 的4个状态文件。

---

## 快速开始

1. 选 3 本对标书（题材相近 + 你喜欢 + 数据好）
2. 先拆 1 本的 Author DNA + Planner（投入最小，收益最大）
3. 写前 3 章时，边写边拆 Unit 和 Reference（有针对性地拆）
4. 第 4 章开始，池子内容够多了，写作效率会明显提升
5. 每写完一章（人工定稿后），决定是否将关键单元入池
