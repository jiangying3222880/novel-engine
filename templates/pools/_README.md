# 素材池 — 总览（项目级）

**池子是 Agent 自动拆解出来的，不是手动建出来的。空池子没有价值。**

本目录是**当前项目的素材池**，与项目共生。对标书拆解的内容都存在这里。**每本书独立建池，跨项目不共享。**

---

## 双层素材体系

Novel Engine 采用 **用户级 + 项目级** 双层素材体系：

| 层级 | 位置 | 内容 | 共享范围 | 增长方式 |
|------|------|------|---------|---------|
| **用户级 library/** | 技能内置 | 通用方法论 + 题材风格包 + 知识库 + 平台指南 | 跨所有项目共享 | 写的书越多，积累越丰富 |
| **项目级 素材池/** | 项目目录 | 本书对标书拆解内容 | 仅当前项目 | 随项目创建，随项目归档 |

**使用关系**：
- 用户级 library/ 是**通用打底**——写什么书都能用的方法论和参考
- 项目级 素材池/ 是**精准校准**——针对本书的对标书拆解，更精准但只适用于本书
- 写特定题材时，先加载对应题材包（通用风格参考），再加载本书对标书拆解（精准校准）

> 详细的用户级素材库说明见 `library/_README.md`。

---

## 为什么要有池子

AI 写作最大的问题是"风格漂移"和"情节套路化"。池子的作用是：

1. **风格锚定**：Author DNA 让句式/节奏/词汇保持一致
2. **事件参考**：Unit Pool 让你写任何事件都有现成的"好写法"可以对标
3. **结构模板**：Planner Pool 让卷纲/章节节奏有成熟作品的结构打底
4. **场景素材**：Reference Pool 让同类场景的写法直接可借鉴
5. **知识储备**：Knowledge Pool 把对标书里用到的专业知识提前存好，不用临时查

---

## 谁来拆解？—— Agent 自动执行

> **重要：拆解是 Agent 的工作，不是用户的工作。**
>
> 用户只需提供对标书（书名/文本文件），Agent 负责读取、分析、判断、入池。用户不需要自己读对标书、不需要手动填表。
>
> 只有当用户要求手动修改某条拆解结果时，才开放编辑权限。

---

## 拆解成本（Agent 自动执行的预估时间）

| 拆解项目 | Agent 耗时 | 产出价值 |
|----------|-----------|----------|
| 选3本对标书（用户选，Agent 给建议） | 10分钟 | ★★★ |
| 拆1本 Planner（卷结构） | 20-40分钟 | ★★★★★ |
| 拆1本 Author DNA（风格） | 15-30分钟 | ★★★★ |
| 拆1本 Unit（前10章事件） | 40-80分钟 | ★★★★ |
| 拆1本 Reference（精选段落） | 20-40分钟 | ★★★ |
| 拆1本 Knowledge（知识点） | 10-20分钟 | ★★ |

**拆1本对标书的 Agent 总耗时：约 1.5-3 小时**（取决于深度和书的长度）

> 建议：至少拆 3 本（结构 + 文笔 + 节奏各一本），但第一本可以先拆细，后面两本只拆核心部分。

## 入池深度档位（影响token消耗）

| 档位 | 包含内容 | 预估额外token/章 | 适合阶段 |
|------|----------|-----------------|----------|
| 轻量 | Planner + Author DNA | 2-3KB | 刚开始写、预算有限 |
| 标准 | 以上 + Reference 精选段落 | 4-6KB | 稳定写作中 |
| 全量 | 五项全拆 | 8-12KB | 追求极致质量 |

> 池子内容在初始化时一次性拆解完成，后续写作中不自动增长。如后续需要补充新的对标书，手动添加即可。

## 五个池子的分工

| 池子 | 存什么 | 什么时候用 | 组织方式 |
|------|--------|-----------|----------|
| `unit/` | 事件单元（拆成原子的关键场景） | 写某类事件前参考 | 按来源分目录：`_source_书名/` |
| `author_dna/` | 作者写作习惯（句式/节奏/词汇/文风） | 写作全程保持风格一致 | 每本书一份DNA |
| `knowledge/` | 对标书用到的事实知识 | 涉及特定领域时取用 | 按领域分文件 |
| `reference/` | 写作技巧 + 精选段落 | 写同类场景时调取参考 | techniques（方法论） + samples（实战样本） |
| `planner/` | 结构决策（卷结构/伏笔编排/情绪曲线/节奏） | 规划全书/卷结构时参考 | 每本书一份结构分析 |

## 两阶段拆解流程

参考 oh-story 拆书方法论，采用"先预览后深度"的两阶段模式，避免一上来就全文暴力拆解导致的上下文溢出。

### 阶段一：快速预览（先拆前3章 + 整体结构）

用户指定对标书后，Agent **先只拆前3章 + 全书整体结构**，产出一份"拆解预览报告"，包含：

1. **Author DNA 预览**：句式特征、词汇偏好、对话风格（基于前3章统计）
2. **Planner 预览**：前3章结构、开篇钩子类型、世界观释放方式
3. **Reference 预览**：3-5个精选段落 + 初步判断（符合/不符合入池标准）
4. **文风特征摘要**：一句话概括这本书的文风质感
5. **适配度评估**：这本书和当前项目的题材/风格匹配度（1-10分）

**用户确认预览方向后**，再进入阶段二的深度拆解。如果用户觉得这本书不对味，可以直接换书，不浪费时间。

### 阶段二：深度拆解（按档位全量拆）

用户确认后，Agent 按选定的深度档位继续拆解：

- **轻量档**：完成 Planner（全卷结构）+ Author DNA（全书风格统计）
- **标准档**：以上 + Reference（精选段落，按判断标准筛选）
- **全量档**：五项全拆 + Unit（前20章事件单元）

拆解完成后，所有内容按模板填入对应池子目录。

## Agent 拆解判断标准（非常重要）

Agent 拆解对标书时，不是"全量复制"，而是带着**分析框架**去读。以下是每个池子的入池判断标准。

### 各池子入池标准

| 池子 | 入池标准 | 判断方法 |
|------|----------|----------|
| **Author DNA** | 存在可复现的句式/节奏/词汇模式 | 通读前3章，统计句长/段长/高频词/重复句型。有显著模式 → 入池 |
| **Planner** | 存在清晰的卷结构/转折点/伏笔布局/节奏规律 | 标注卷首/卷末/关键转折章节。有明确结构 → 入池 |
| **Unit** | 事件单元完整、有决策点、有后果、有情绪变化 | 单个事件有"起因→决策→结果→情绪变化"闭环。四者齐全 → 入池 |
| **Reference** | 段落符合"非AI味"5条标准（见下方） | 逐段检验 5 条标准。符合 ≥4 条 → 入池 |
| **Knowledge** | 涉及可查证的事实信息 | 信息可溯源、可在小说中复用 → 入池 |

### Reference 入池的 5 条判断标准（逆向应用 anti-ai.md）

| # | 判断项 | 入池条件 |
|---|--------|----------|
| 1 | 乒乓球对话 | 非乒乓球式（对话与动作穿插，非纯粹一问一答） → 入池候选 |
| 2 | 段末升华 | 段末落物（动作/声响/画面），非感慨总结 → 入池候选 |
| 3 | 解释腔 | 不解释原因，只呈现结果 → 入池候选 |
| 4 | 感官细节 | 包含至少2种感官细节（视觉+听觉/触觉/嗅觉） → 入池候选 |
| 5 | 信息留白 | 不主动替读者剖析，留解读空间 → 入池候选 |

**判定规则**：同时满足 ≥4 条 → 入池。满足 ≤2 条 → 不入池（说明这段本身不值得学习）。

### Unit 入池额外标准

Unit 除了满足事件完整性，还必须标注：

- **情绪标记**（-9 到 +9）：该事件的情绪烈度。负数=负面（压抑/恐惧/悲伤），正数=正面（爽/燃/感动），0=中性
- **节奏类型**：快节奏（打斗/追逐/对峙）/ 慢节奏（日常/过渡/铺垫）/ 爆发点（高潮/揭秘/反转）

> 情绪标记的作用：让 Agent 写某类情绪强度的场景时，可以快速找到对标事件，而不是凭感觉瞎写。

## 入池原则（非常重要）

### 原则一：对标书驱动，每本书独立建池

`素材池/` 随项目创建，随项目归档。每本书独立建池，不跨书复用。这保证了一本书的 `素材池/` 始终服务于这本书的题材和风格，不存在不同题材间的风格污染。

- 写完一本书 → `素材池/` 随项目归档
- 开新书 → 找 1-3 本新对标书 → `素材池/` 新建，从零填充

### 原则二：只放经过验证的高质量内容

对标书（市场验证过的作品）是池子的主要来源。自己写的内容（无论感觉多好）在未经长时间检验前不入池，避免用自我评价拉低池子的平均水平。

> 如果某段自己写得特别好、想保留参考，直接在章节正文里标备注即可，不必入池。

### 原则三：判断标准独立，不盲目摘抄

入池前必须经过判断（按上方的 5 条标准 + 各池子专属标准）。不是所有内容都值得入池——对标书里也有写得平的章节、过渡章节、水字数章节，这些不值得入库。

**Agent 的任务是"筛选 + 分析"，不是"复制 + 粘贴"。**

### 原则四：池子是静态的，写作期不自动增长

对标书拆解在项目初始化阶段完成（或分阶段补），写作过程中池子不自动增长。需要补充新的对标书时手动添加。

### 原则五：按需加载，不常驻

池子文件量大，写作时只调取当前需要的部分。强制加载的只有 `故事/真相/` 的6个状态文件（含 objects/timeline）。

## 拆解产物格式要求

所有入池内容必须附带"可借鉴点"说明，不能只摘抄原文。可借鉴点从以下维度选取：

- 对应 anti-ai.md 的四大转换原则（心理→动作/解释→结果/对称→不对称/总结→落物）
- 对应 writing-guide.md 的冰山法则和对话不对称原则
- 结构层面的技巧（伏笔编排/节奏控制/信息释放）

> 核心思路：**让 Agent 带着"分析框架"去读文本，而不是让 Agent 漫无目的地全文照搬。**

## 快速开始

1. 用户选 1-3 本对标书（题材相近 + 喜欢 + 数据好）
2. Agent 先做**快速预览**（前3章 + 整体结构），生成预览报告
3. 用户确认后，Agent 按选定档位**深度拆解**
4. 写前 3 章时，边写边根据需要补充 Unit 和 Reference
5. 第 4 章开始，池子内容够多了，写作效率会明显提升
