# ne-short · 短篇创作

## 一、与长篇的关键差异

| | 长篇 | 短篇 |
|---|---|---|
| 项目结构 | 建 `故事/真相/` 六状态 | **不建项目**，不走 truth |
| 细纲 | 四维骨架 | **憋压三段式**（长篇去掉多层嵌套，只留单弧） |
| 细纲门 | 有 | **有**（v1.9 起短篇也走细纲门） |
| 门禁 | `settle` 每章 | 段二每节 ≥2000 字 |

> 短篇模板继承长篇细纲模板的结构，改长篇结构时需同步核对对应节。
> 长篇模板在 `../ne-outline/templates/细纲模板.md`，短篇模板在 `./templates/short-story-template.md`。

## 二、憋压三段式

完整引擎见 `./references/short-story.md`，套路库见 `./references/short-story-engines.md`，节奏溯源见 `./references/short-story-rhythm-origin.md`。

```
段一 立压   迅速建立处境与欲望，埋下读者期待
段二 憋压   反复加压，每次接近释放又被打断（每节 ≥2000 字）
段三 释放   一次性兑现，不给尾巴
```

**驱动标注**（与长篇共用内核）：
```
- 制造什么期待（读者在等什么）：
- 第几段后引爆：
- 憋压到什么程度给：
```

## 三、写前预检（细纲门）

短篇细纲同样要过门：结构硬检 + 删节推理软检。缺一项不许动笔。

写前必填内核三联（目标/阻力/后果），规则同 `../ne-outline/SKILL.md` §一。

## 四、去 AI 味

短篇同样适用 `../ne-review/references/anti-ai.md` 及其配套文件。
检验按 `../ne-review/SKILL.md` 执行——**但短篇不需要落库**，跳过 S4。

## 五、门禁

段二每节 ≥2000 字是硬要求。整体质量校验可跑：

```
python ../ne-tools/runtime/verify.py --root <项目根> --scope execution
```

（短篇通常没有项目根，手工核对字数即可。）
